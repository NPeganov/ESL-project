# timer_service

## Назначение

`timer_service` один раз подготавливает общую временную инфраструктуру приложения: legacy clock driver, LFCLK и app_timer. Он не создаёт прикладные таймеры и не управляет их жизненным циклом.

## API

```c
bool timer_service_init(void);
```

Повторный вызов после успешной инициализации возвращает true.

## Порядок инициализации

1. Проверяет, инициализирован ли legacy clock driver.
2. Если нет, вызывает `nrf_drv_clock_init()`.
3. Запрашивает LFCLK.
4. Ожидает, пока LFCLK перейдёт в состояние running.
5. Вызывает `app_timer_init()`.
6. Сохраняет признак успешной инициализации.

При ошибке clock driver или app_timer функция возвращает false.

## Владение ресурсами

После успешного вызова app_timer framework готов к созданию таймеров другими модулями. В текущем приложении:

- `leds_control` создаёт один repeated timer с периодом 10 мс;
- `btn_hw` создаёт one-shot debounce timer;
- `btn` создаёт one-shot double-press timer.

Эти модули владеют собственными таймерами; `timer_service` только обеспечивает общую инфраструктуру.

## Ограничения

Функцию следует вызвать до `lc_init()` и `btn_init()`. Она не запускает прикладные процессы, не обрабатывает события и не предоставляет API для чтения времени.
