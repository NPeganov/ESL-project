# Аппаратная PWM-система

## Назначение и место в проекте

PWM — универсальный низкоуровневый модуль для формирования аппаратных сигналов с широтно-импульсной модуляцией на периферии PWM микроконтроллера nRF52840.

Модуль не знает о светодиодах, их логических номерах, назначении или конфигурации платы. Он управляет четырьмя аппаратными PWM-каналами и принимает для каждого канала GPIO и полярность активного уровня.

Публичный интерфейс находится в `pwm.h`. Реализация разделена по функциональным обязанностям:

~~~ text
                    application
                         |
                         v
                      pwm.h
                    public API
                         |
                         v
                       pwm.c
              peripheral and runtime
                    /         \
                   v           v
             pwm_timing.c   pwm_sequence.c
             clock/period   sequence encoding
                    \         /
                     pwm_internal.h
                  internal interfaces
~~~

- `pwm.c` управляет жизненным циклом периферии, хранит текущие настройки каналов и обновляет буфер воспроизведения.
- `pwm_timing.c` выбирает базовую частоту PWM и значение периода.
- `pwm_sequence.c` преобразует логические значения duty и polarity в формат аппаратной последовательности.
- `pwm_internal.h` содержит тип и объявления функций, используемых только внутри PWM-модуля.

Ни один из этих модулей не реализует логику конкретного устройства или светодиода.

## Публичный интерфейс

### Конфигурация

Количество каналов задаётся `PWM_CHANNEL_COUNT` и равно четырём.

`pwm_channel_t` идентифицирует канал: `PWM_CHANNEL_0` … `PWM_CHANNEL_3`.

Для каждого канала задаются:

- `pin` — GPIO, подключаемый к соответствующему выходу PWM;
- `polarity` — активный логический уровень: `PWM_POLARITY_ACTIVE_HIGH` или `PWM_POLARITY_ACTIVE_LOW`.

Общая конфигурация `pwm_config_t` содержит запрошенную частоту `frequency_hz` и массив настроек всех четырёх каналов. Все каналы работают с одной частотой, но могут иметь разные GPIO и полярность.

В текущей реализации все четыре канала должны иметь допустимые GPIO. Неиспользуемый канал не исключается из конфигурации: для него также требуется указать корректный вывод.

### Инициализация

~~~ c
bool pwm_init(pwm_config_t const *config);
~~~

Функция настраивает периферию и запускает непрерывное воспроизведение PWM. При успешной инициализации все каналы начинают с duty, равным нулю, то есть в неактивном состоянии.

Возвращаемое значение:

- `true` — инициализация nrfx PWM прошла успешно и запуск непрерывного воспроизведения выполнен;
- `false` — запрошенная частота не поддерживается либо `nrfx_pwm_init()` вернула ошибку.

Нулевой указатель конфигурации, некорректные GPIO и значения polarity являются нарушением предусловий и проверяются через `ASSERT`, а не возвращаются как штатная ошибка.

Модуль рассчитан на однократную инициализацию. Публичной функции остановки или деинициализации нет. `pwm_set()` следует вызывать только после успешного `pwm_init()`.

### Установка duty

~~~ c
void pwm_set(pwm_channel_t channel, uint8_t duty);
~~~

Значение `duty` задаётся в диапазоне 0…255:

| Duty | Значение |
|---:|---|
| 0 | Канал неактивен весь период |
| 255 | Канал активен весь период |
| 1…254 | Промежуточная скважность |

Смысл duty одинаков для обеих полярностей: это доля периода, в течение которой выход находится в активном логическом состоянии.

Функция не изменяет аппаратную последовательность непосредственно. Она сохраняет новое значение канала в runtime-состоянии. Новое значение попадёт в последовательность при очередном обновлении буфера, поэтому между вызовом `pwm_set()` и изменением физического выхода возможна задержка.

Номер канала проверяется через `ASSERT`.

## Выбор частоты и разрешения

### Аппаратные ограничения

PWM периферия использует источник 16 МГц и предоставляет восемь вариантов базовой частоты:

| Базовая частота | Делитель |
|---:|---:|
| 16 МГц | 1 |
| 8 МГц | 2 |
| 4 МГц | 4 |
| 2 МГц | 8 |
| 1 МГц | 16 |
| 500 кГц | 32 |
| 250 кГц | 64 |
| 125 кГц | 128 |

Значение периода `top_value` должно находиться в диапазоне 3…32767. Частота выходного сигнала определяется выбранной базовой частотой и числом тактов в периоде:

~~~ text
PWM frequency = base clock frequency / top_value
~~~

Таким образом, допустимый общий диапазон запрашиваемой частоты составляет приблизительно 4 Гц…5,33 МГц.

### Алгоритм выбора

`pwm_timing_select()` выбирает не просто ближайшую частоту из всех возможных вариантов. Его приоритет — использовать самую быструю базовую частоту, при которой округлённое значение периода помещается в аппаратные границы.

Алгоритм:

1. Проверяет, входит ли запрошенная частота в поддерживаемый диапазон.
2. Начинает с базовой частоты 16 МГц.
3. Вычисляет ближайшее целое значение `top_value` для запрошенной частоты.
4. Если значение находится в диапазоне 3…32767, выбирает эту базовую частоту.
5. Иначе переходит к следующей, вдвое более медленной базовой частоте и повторяет расчёт.

Более быстрая базовая частота позволяет использовать больше тактов на период и тем самым обеспечивает более высокое разрешение duty. После выбора настроек модуль также вычисляет фактическую частоту, получаемую с выбранными целочисленными параметрами.

Если частота вне поддерживаемого диапазона, функция возвращает `false`, а `pwm_init()` также завершается с ошибкой.

## Формирование PWM-последовательности

### Формат данных

Для воспроизведения используется режим `NRF_PWM_LOAD_INDIVIDUAL`: один элемент последовательности содержит отдельное 16-битное значение для каждого из четырёх каналов — `channel_0` … `channel_3`.

Поэтому последовательность содержит четыре 16-битных слова, хотя представляет один набор значений каналов на один PWM-период.

В `pwm.c` находится постоянный буфер `m_sequence`. Он размещён в RAM и имеет время жизни всего модуля, поскольку периферия читает его через EasyDMA. Сам дескриптор `nrf_pwm_sequence_t` создаётся локально в `pwm_driver_start()`: драйвер использует его для настройки регистров при запуске, а массив значений остаётся постоянным.

### Преобразование duty

Для каждого канала функция `pwm_channel_value()` переводит duty 0…255 в число активных тактов периода с округлением к ближайшему целому:

~~~ text
active_ticks = round(duty * top_value / 255)
~~~

Затем формируется значение сравнения:

~~~ text
compare_value = top_value - active_ticks
~~~

Такое представление обеспечивает ожидаемые граничные значения:

- duty = 0: активных тактов нет, значение сравнения равно `top_value`;
- duty = 255: активен весь период, значение сравнения равно нулю.

### Полярность

В старшем бите 16-битного значения PWM-последовательности задаётся направление активного фронта:

- бит 15 сброшен — rising-edge;
- бит 15 установлен — falling-edge.

Для active-high используется rising-edge, для active-low — falling-edge. Поэтому логическое значение duty не требуется инвертировать на уровне API: модуль кодирует нужную полярность при формировании аппаратного значения.

Отдельно для active-low каналов при настройке GPIO применяется `NRFX_PWM_PIN_INVERTED`. Этот флаг задаёт высокий уровень GPIO в состоянии покоя периферии. Он решает задачу начального/неактивного уровня вывода и не заменяет бит полярности в значении PWM-последовательности.

## Непрерывное воспроизведение и обновление

### Запуск

`pwm_driver_start()` инициализирует экземпляр nrfx PWM и запускает `nrfx_pwm_simple_playback()` с флагами:

- `NRFX_PWM_FLAG_LOOP` — непрерывно повторять воспроизведение;
- `NRFX_PWM_FLAG_SIGNAL_END_SEQ0` и `NRFX_PWM_FLAG_SIGNAL_END_SEQ1` — получать события завершения обеих последовательностей;
- `NRFX_PWM_FLAG_NO_EVT_FINISHED` — не генерировать ненужное событие завершения конечного воспроизведения.

При использовании `simple_playback` драйвер назначает одну и ту же последовательность обоим аппаратным слотам SEQ0 и SEQ1. Для циклического воспроизведения используются оба слота, поэтому включены оба события завершения, а обработчик выполняет для них одинаковую работу.

В режиме `NRF_PWM_STEP_AUTO` периферия автоматически переходит к следующей последовательности. Каждая последовательность содержит один набор значений каналов, то есть один PWM-период.

### Обновление буфера

Целевой интервал обновления — 10 мс. Это не гарантированный точный интервал: обработчик может обновить буфер только на границе последовательности, то есть не чаще одного раза за PWM-период.

При инициализации целевой интервал переводится в количество PWM-периодов с использованием фактической, а не запрошенной частоты. Количество периодов округляется к ближайшему целому и ограничивается снизу одним периодом.

При каждом событии `END_SEQ0` или `END_SEQ1` обработчик увеличивает счётчик прошедших периодов. Когда счётчик достигает заданного интервала, он сбрасывает счётчик и пересобирает `m_sequence` из последних значений duty и сохранённых настроек polarity.

Таким образом:

- при высокой частоте обновление обычно происходит примерно раз в 10 мс;
- если период PWM длиннее 10 мс, обновление происходит раз в один PWM-период;
- для частот, при которых 10 мс не содержит целого числа периодов, фактический интервал округляется до ближайшего числа периодов.

`pwm_set()` может вызываться из основного кода, тогда как обновление последовательности происходит в обработчике прерывания PWM. Массив текущих duty объявлен `volatile`, чтобы изменения, сделанные приложением, считывались при последующем обновлении. Значения разных каналов обновляются независимо; интерфейс не предоставляет атомарной групповой установки всех четырёх каналов.

## Обработка ошибок и аппаратная конфигурация

PWM-модуль использует аппаратный экземпляр PWM0. В конфигурации проекта должны быть включены `NRFX_PWM_ENABLED` и `NRFX_PWM0_ENABLED`, а исходный файл драйвера `nrfx_pwm.c` должен входить в сборку вместе с файлами PWM-модуля.

`nrfx_pwm_init()` возвращает код ошибки, который проверяется реализацией. Если инициализация не удалась, `pwm_driver_start()` возвращает `false`, а `pwm_init()` передаёт эту ошибку вызывающему коду.

После успешной инициализации вызывается `nrfx_pwm_simple_playback()`. Эта функция не возвращает код статуса: без флага `NRFX_PWM_FLAG_START_VIA_TASK` она непосредственно запускает воспроизведение и возвращает ноль. Адрес аппаратной задачи возвращается только при использовании `START_VIA_TASK`. Поэтому результат вызова не проверяется как `NRFX_SUCCESS` — такая проверка была бы некорректной и не могла бы обнаружить ошибку запуска.

После вызова `simple_playback()` функция считает запуск выполненным и возвращает `true`. Следовательно, `pwm_init()` сообщает об ошибке при неподдерживаемой частоте или неудачной инициализации nrfx; отдельного кода ошибки запуска у используемого API нет.

Приоритет прерывания PWM задан внутри реализации значением 6. Это аппаратная деталь модуля, а не параметр публичной конфигурации.

## Границы ответственности

PWM-модуль отвечает только за:

- настройку аппаратного PWM;
- назначение GPIO и активной полярности четырём каналам;
- преобразование duty в аппаратные значения;
- непрерывное воспроизведение и периодическое обновление последовательности.

Он не отвечает за:

- назначение каналов конкретным светодиодам или другим устройствам;
- преобразование RGB/HSV;
- плавное изменение яркости или генерацию пользовательских последовательностей;
- управление режимами приложения;
- выбор временных параметров конкретного эффекта.

Эти задачи должны оставаться на более высоких уровнях приложения.
