# Внутренний модуль color

## Назначение

`color` содержит целочисленные преобразования между RGB и HSV, а также перевод процентного значения в 8-битную шкалу.

Модуль является внутренней зависимостью `leds_pwm`. Он не управляет GPIO, PWM, таймерами или состоянием светодиодов. Все функции работают только с переданными значениями и не хранят собственное состояние.

Исходные файлы:

- `color.h` — внутренние типы и объявления функций;
- `color.c` — реализация преобразований.

## Представления цвета

### RGB

Тип `color_rgb_t` содержит три независимых компонента:

| Поле | Диапазон | Значение |
|---|---:|---|
| `red` | 0…255 | Интенсивность красного |
| `green` | 0…255 | Интенсивность зелёного |
| `blue` | 0…255 | Интенсивность синего |

Это 8-битная шкала каждого канала. Значение 0 означает отсутствие соответствующего компонента, 255 — максимальное значение.

### HSV

Тип `color_hsv_t` содержит:

| Поле | Диапазон | Значение |
|---|---:|---|
| `hue` | 0…359 | Оттенок в градусах |
| `saturation` | 0…100 | Насыщенность в процентах |
| `value` | 0…100 | Значение/яркость в процентах |

Hue задаёт положение на цветовом круге. Saturation = 0 соответствует оттенкам серого. Value = 0 соответствует чёрному независимо от Hue и Saturation.

Диапазоны являются контрактом вызывающего кода. Функции модуля не выполняют ASSERT и не ограничивают входные значения.

## Публичные для внутреннего уровня функции

### Процент в 8-битное значение

```c
uint8_t color_percent_to_value(uint8_t percent);
```

Переводит процент 0…100 в диапазон 0…255 с округлением к ближайшему целому:

```c
(percent * 255 + 50) / 100
```

Функция используется как для HSV Value, так и для яркости отдельного жёлтого LED.

Она не проверяет диапазон аргумента. Вызывающий код обязан передавать процент не больше 100. В текущей архитектуре публичные setter-функции `leds_pwm` проверяют это предусловие через ASSERT.

### HSV → RGB

```c
color_rgb_t color_hsv_to_rgb(color_hsv_t hsv);
```

Функция преобразует Hue 0…359 градусов и Saturation/Value 0…100% в три 8-битных RGB-компонента.

Основные этапы:

1. Value переводится в 8-битную шкалу через `color_percent_to_value()`.
2. Если Saturation равна нулю, все RGB-компоненты получают одно и то же значение Value.
3. Цветовой круг делится на шесть секторов по 60 градусов.
4. Для текущего сектора вычисляются промежуточные значения `p`, `q` и `t`.
5. В зависимости от сектора эти значения распределяются между R, G и B.

Положение внутри сектора вычисляется целочисленно:

```c
hue_position = hue * 6;
sector = hue_position / 360;
fraction = hue_position % 360;
```

Промежуточные значения:

```c
p = (value * (100 - saturation) + 50) / 100;

q = (value * (100 - (saturation * fraction + 180) / 360) + 50) / 100;

t = (value * (100 - (saturation * (360 - fraction) + 180) / 360) + 50) / 100;
```

Здесь `value` уже находится в диапазоне 0…255, а `saturation` — в процентах. Добавление половины делителя реализует округление в целочисленной арифметике.

Распределение компонентов по секторам:

| Сектор | Диапазон Hue | Red | Green | Blue |
|---:|---|---|---|---|
| 0 | 0…59° | Value | t | p |
| 1 | 60…119° | q | Value | p |
| 2 | 120…179° | p | Value | t |
| 3 | 180…239° | p | q | Value |
| 4 | 240…299° | t | p | Value |
| 5 | 300…359° | Value | p | q |

Все вычисления выполняются целыми числами, без floating-point операций.

### RGB → HSV

```c
color_hsv_t color_rgb_to_hsv(color_rgb_t rgb);
```

Функция определяет максимальный и минимальный RGB-компоненты:

```text
max = max(red, green, blue)
min = min(red, green, blue)
delta = max - min
```

Value вычисляется как максимальный RGB-компонент, переведённый в проценты с округлением к ближайшему целому:

```c
value = (max * 100 + 127) / 255;
```

Дальнейшие случаи обрабатываются отдельно:

- Если `max == 0`, цвет чёрный: Saturation = 0, Hue = 0.
- Иначе Saturation рассчитывается как `(delta * 100 + max / 2) / max`.
- Если `delta == 0`, все каналы равны: Hue = 0.
- В остальных случаях Hue определяется по каналу, имеющему максимальное значение.

Формулы Hue:

```c
// Red is maximum.
hue = 60 * (green - blue) / delta;
if (hue < 0) hue += 360;

// Green is maximum.
hue = 120 + 60 * (blue - red) / delta;

// Blue is maximum.
hue = 240 + 60 * (red - green) / delta;
```

В коде используются знаковые промежуточные значения для корректного вычитания RGB-компонентов. Деление целочисленное: дробная часть Hue отбрасывается. Поэтому Hue возвращается в целых градусах.

Для чёрного и любых оттенков серого Hue математически не определён; модуль использует условное значение 0.

## Точность и обратимость

Преобразования используют целочисленную арифметику и округление. RGB имеет 256 уровней на канал, тогда как HSV задаёт Hue целыми градусами, а Saturation и Value целыми процентами.

Поэтому последовательное преобразование RGB→HSV→RGB или HSV→RGB→HSV не обязано возвращать исходные значения побитно. Небольшое отличие является следствием квантования и округления, а не сохранения скрытого состояния.

Именно поэтому `leds_pwm` хранит оба представления отдельно: getter возвращает то представление, которое было задано последним setter, а второе представление сохраняется как результат преобразования.

## Границы ответственности

`color`:

- не знает о плате PCA10059;
- не знает о PWM-каналах и полярности LED;
- не обращается к аппаратным регистрами;
- не проверяет диапазоны через ASSERT;
- не хранит текущий цвет;
- не реализует цветовые эффекты или временную логику.

Модуль предоставляет только чистые преобразования значений. Управление физическими выходами остаётся ответственностью `leds_pwm`.
