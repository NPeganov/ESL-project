# led_controller

`led_controller` --- модуль управления одним светодиодом и выполнением повторяющейся последовательности его плавного включения и выключения. Он объединяет `fade`, `soft_pwm` и низкоуровневый интерфейс `leds`.

Контроллер не реализует интерполяцию яркости и не формирует PWM-фронты самостоятельно. Он задаёт порядок фаз, запускает и останавливает переходы `fade`, обслуживает программный PWM и связывает его логический выход с выбранным светодиодом.

Основные свойства:

- один экземпляр управляет одним логическим LED;
- один цикл состоит из fade-in и fade-out;
- число циклов задаётся при подготовке;
- между циклами может выполняться дополнительная пауза;
- последовательность можно приостановить и возобновить;
- пауза во время fade сохраняет его прогресс;
- пауза во время межцикловой паузы при возобновлении начинается заново;
- после завершения контроллер возвращается в `IDLE`;
- подготовленную последовательность можно запустить повторно;
- PWM продолжает обслуживаться даже при остановленной последовательности.

# Место в архитектуре

~~~ text
application
    |
    v
led_sequence
    |
    v
led_controller
    |
    +-------------------------+
    |                         |
    v                         v
  fade                     soft_pwm
    |                         |
    | set duty                | output callback
    +------------------------>+
                              |
                              v
                       pwm_led_output()
                              |
                              v
                            leds
                              |
                              v
                             GPIO
                              |
                              v
                         physical LED
~~~

| Модуль | Ответственность |
| --- | --- |
| `led_sequence` | Выбирает контроллеры и управляет последовательностью их выполнения |
| `led_controller` | Управляет фазами одного LED, циклами, паузой, запуском и остановкой |
| `fade` | Рассчитывает промежуточные значения скважности |
| `soft_pwm` | Преобразует скважность в логические состояния ON/OFF |
| `leds` | Преобразует логический индекс LED в GPIO и управляет физическим выходом |

Контроллер знает о `fade_t`, `soft_pwm_t` и публичном интерфейсе
`leds`. Нижележащие модули не знают о последовательности контроллера.

## Разделение fade и soft_pwm

- `fade` меняет требуемую скважность с течением времени;
- `soft_pwm` формирует ON/OFF-состояния на основании последней
  установленной скважности;
- `led_controller` определяет, когда начинается fade-in, когда он
  сменяется fade-out и когда выдерживается межцикловая пауза.

# Модель последовательности

Одна последовательность состоит из заданного количества одинаковых
циклов. Каждый цикл включает две фазы:

1. **Fade-in** --- плавное увеличение скважности от 0 до 100%.
2. **Fade-out** --- плавное уменьшение скважности от 100 до 0%.

Между соседними циклами может быть пауза `pause_duration_ms`.
Она не является частью fade и обслуживается непосредственно
контроллером.

~~~ text
             one cycle
       +-------------------+
       |                   |
       v                   |
    fade-in                |
    0% -> 100%              |
       |                   |
       v                   |
    fade-out               |
    100% -> 0%              |
       |                   |
       +-------------------+
                |
                v
       more cycles remaining?
           /           \\
         yes            no
          |              |
          v              v
   inter-cycle pause   sequence complete
          |
          v
       next fade-in
~~~

Если `pause_duration_ms == 0`, следующий fade-in начинается сразу
после завершения fade-out. Иначе контроллер переходит в фазу `PAUSE`.

## Параметры

Параметры, задаваемые через `led_controller_init()`:

| Параметр | Назначение |
| --- | --- |
| `pwm_period_us` | Период программного PWM в микросекундах |
| `fade_duration_ms` | Продолжительность каждого fade-in и fade-out |
| `pause_duration_ms` | Пауза между циклами |

Параметры, задаваемые через `led_controller_prepare()`:

| Параметр | Назначение |
| --- | --- |
| `led_idx` | Логический индекс светодиода |
| `cycle_count` | Количество полных циклов fade-in/fade-out |

Продолжительность задаётся для каждой fade-фазы отдельно.
Без межцикловой паузы номинальная продолжительность одного цикла
равна примерно двум продолжительностям fade. Фактическое время
зависит от частоты вызова `led_controller_process()` и временной
модели модуля `fade`.

# Состояния контроллера

Публичный тип `led_controller_state_t` описывает три состояния:

~~~ c
typedef enum {
    LED_CONTROLLER_STATE_IDLE,
    LED_CONTROLLER_STATE_RUNNING,
    LED_CONTROLLER_STATE_PAUSED
} led_controller_state_t;
~~~

## IDLE

Контроллер не выполняет последовательность.

Состояние используется:

- сразу после успешного `led_controller_init()`;
- после `led_controller_prepare()`;
- после нормального завершения всех циклов;
- после аварийного восстановления при некорректном значении фазы.

После `init()` контроллер ещё не подготовлен: `cycle_count == 0`.
Вызов `resume()` до успешного `prepare()` некорректен по контракту
и безопасно игнорируется.

После `prepare()` состояние также равно `IDLE`, но последовательность
уже подготовлена и может быть запущена через `resume()`.

После нормального завершения `cycle_count` сохраняется. Поэтому
повторный `resume()` запускает ту же последовательность заново.

## RUNNING

Контроллер выполняет одну из фаз:

- `FADE_IN`;
- `FADE_OUT`;
- `PAUSE`.

В этом состоянии вызывающий код должен регулярно вызывать
`led_controller_process()`.

## PAUSED

Последовательность приостановлена вызовом `led_controller_pause()`.

Поведение зависит от текущей фазы:

- во время fade контроллер останавливает `fade`, сохраняя прогресс;
- во время межцикловой паузы контроллер перестаёт увеличивать её
  программный счётчик.

Сам PWM продолжает обслуживаться вызовами
`led_controller_process()`, поэтому последняя установленная яркость,
в том числе промежуточная, сохраняется.

При возобновлении fade продолжается с сохранённого прогресса.
Межцикловая пауза начинается заново с нуля.

# Внутренние фазы

Фазы объявлены приватным перечислением в `led_controller.c`:

~~~ c
enum {
    LED_CONTROLLER_PHASE_FADE_IN,
    LED_CONTROLLER_PHASE_FADE_OUT,
    LED_CONTROLLER_PHASE_PAUSE
};
~~~

Поле `phase` в `led_controller_t` хранит одну из этих величин.
Оно не является публичным типом API: вызывающий код не должен
читать или изменять его напрямую.

## FADE_IN

При входе в фазу вызывается:

~~~ c
fade_start(
    &controller->fade,
    0,
    FADE_PERCENT_MAX,
    controller->fade_duration_ms);
~~~

Начальное значение равно 0%, целевое --- 100%.

Когда `fade_process()` завершает переход, контроллер обнаруживает,
что fade больше не активен и не приостановлен, и запускает
`FADE_OUT`. Переключение фазы выполняется в том же вызове
`led_controller_process()`, в котором обнаружено завершение
fade-in. Первый шаг fade-out будет обработан при последующих вызовах.

## FADE_OUT

При входе в фазу вызывается:

~~~ c
fade_start(
    &controller->fade,
    FADE_PERCENT_MAX,
    0,
    controller->fade_duration_ms);
~~~

После завершения fade-out контроллер увеличивает
`cycles_completed`.

Затем возможны три варианта:

1. Если `cycles_completed >= cycle_count`, последовательность
   завершена: состояние меняется на `IDLE`, а
   `led_controller_process()` возвращает `true`.
2. Если циклы остались и `pause_duration_ms == 0`, сразу запускается
   следующий fade-in.
3. Если циклы остались и пауза ненулевая, контроллер сохраняет
   временную отметку SysTick, обнуляет `pause_elapsed_ms` и переходит
   в `PAUSE`.

К моменту завершения fade-out скважность уже установлена в 0%.
Поэтому при нормальном завершении дополнительное выключение PWM
не требуется.

## PAUSE

В этой фазе контроллер ожидает межцикловую паузу.

Проверка времени выполняется через:

~~~ c
nrfx_systick_test(
    &controller->pause_start,
    LED_CONTROLLER_PAUSE_UPDATE_INTERVAL_MS * 1000);
~~~

Интервал опроса равен 1 мс и задаётся собственной константой
контроллера `LED_CONTROLLER_PAUSE_UPDATE_INTERVAL_MS`. Он намеренно
не зависит от `FADE_UPDATE_INTERVAL_MS`: контроллер не должен
использовать внутреннюю временную константу нижележащего модуля.

После истечения интервала контроллер:

1. сохраняет новую временную отметку SysTick;
2. увеличивает `pause_elapsed_ms` на один интервал;
3. проверяет, достигнута ли `pause_duration_ms`;
4. если пауза завершена, обнуляет её счётчик и запускает fade-in.

За один вызов `led_controller_process()` счётчик увеличивается
не более чем на один шаг. Пропущенные интервалы не компенсируются.
Редкие вызовы обработчика могут сделать фактическую паузу длиннее
заданной.

# Жизненный цикл

Обычная последовательность использования API:

~~~ text
leds_init()
     |
     v
nrfx_systick_init()
     |
     v
led_controller_init()
     |
     v
led_controller_prepare()
     |
     v
led_controller_resume()
     |
     v
led_controller_process()  <--- periodic calls
     |
     v
returns true on completion
~~~

## Инициализация: `led_controller_init()`

~~~ c
bool led_controller_init(
    led_controller_t *controller,
    uint32_t pwm_period_us,
    uint32_t fade_duration_ms,
    uint32_t pause_duration_ms);
~~~

Функция инициализирует экземпляр контроллера и его нижележащие
модули.

### Предварительные условия

До вызова должны быть выполнены:

1. `leds_init()` --- GPIO светодиодов настроены как выходы.
2. `nrfx_systick_init()` --- общий счётчик SysTick запущен.
3. `pwm_period_us` ненулевой и находится в диапазоне таймаута,
   поддерживаемом `nrfx_systick_test()`.

Инициализация SysTick выполняется один раз на уровне приложения
(сейчас это `main()`). Её не следует повторять в каждом экземпляре
контроллера: SysTick является общим аппаратным счётчиком, который
используют также `fade`, `soft_pwm` и другие части приложения.

### Порядок инициализации

Функция:

1. проверяет указатель `controller`;
2. сохраняет длительности fade и межцикловой паузы;
3. обнуляет счётчики циклов и паузы;
4. устанавливает индекс LED в 0;
5. устанавливает начальную фазу `FADE_IN` и состояние `IDLE`;
6. сбрасывает флаг `initialized`;
7. вызывает `soft_pwm_init()`, передавая callback
   `pwm_led_output()` и указатель на контроллер;
8. инициализирует `fade`, передавая ему созданный экземпляр PWM;
9. устанавливает `initialized = true`.

Если указатель равен `NULL` или `soft_pwm_init()` возвращает
ошибку, функция возвращает `false`.

### Почему LED 0 выбирается до soft_pwm_init()

`soft_pwm_init()` безусловно вызывает callback с логическим
состоянием OFF, чтобы привести физический выход в известное состояние.

Callback контроллера обращается к `controller->led_idx` и вызывает
`led_off(controller->led_idx)`. Поэтому до `soft_pwm_init()`
поле `led_idx` уже установлено в 0. Для используемой платы это
допустимый индекс.

`leds_init()` должен быть выполнен заранее, иначе GPIO ещё не
настроены как выходы.

## Подготовка: `led_controller_prepare()`

~~~ c
void led_controller_prepare(
    led_controller_t *controller,
    uint32_t led_idx,
    uint32_t cycle_count);
~~~

Функция выбирает светодиод и задаёт число циклов.

Вызов игнорируется, если:

- `controller == NULL`;
- контроллер не инициализирован;
- `led_idx >= LEDS_NUMBER`;
- `cycle_count == 0`.

Количество светодиодов `LEDS_NUMBER` доступно через интерфейс
`leds.h` и соответствует конфигурации текущей платы.

При корректных аргументах функция:

1. устанавливает скважность PWM в 0%, выключая прежний LED;
2. записывает новый `led_idx`;
3. явно выключает выбранный LED;
4. сохраняет `cycle_count`;
5. обнуляет `cycles_completed` и `pause_elapsed_ms`;
6. устанавливает фазу `FADE_IN`;
7. переводит контроллер в `IDLE`.

### Повторная подготовка

`prepare()` заменяет текущую последовательность независимо от
состояния контроллера: `RUNNING`, `PAUSED` или `IDLE`.

Если контроллер выполнял fade, старый PWM сначала выключается.
Если выбран другой LED, новый LED также явно приводится к OFF.
Следующий `resume()` начнёт новую последовательность с нуля.

## Запуск и возобновление: `led_controller_resume()`

~~~ c
void led_controller_resume(led_controller_t *controller);
~~~

### Первый запуск после prepare

Успешный вызов `led_controller_prepare()` обязателен до первого
`resume()`.

После подготовки контроллер находится в `IDLE`, а
`cycle_count` ненулевой. `resume()`:

1. обнуляет `cycles_completed`;
2. обнуляет `pause_elapsed_ms`;
3. запускает fade-in от 0 до 100%;
4. переводит контроллер в `RUNNING`.

Вызов `resume()` до подготовки является ошибкой последовательности
вызовов API. Реализация дополнительно защищена проверкой
`cycle_count == 0` и ничего не делает в таком случае.

### Возобновление после pause

Если состояние равно `PAUSED`:

- при фазе fade вызывается `fade_resume()`, и переход продолжается
  с сохранённого прогресса;
- при фазе `PAUSE` сбрасывается `pause_elapsed_ms` и заново
  сохраняется текущая отметка SysTick.

После этого состояние становится `RUNNING`.

Время, проведённое на паузе, не включается в длительность fade
или межцикловой паузы.

### Повторный запуск после завершения

После нормального завершения контроллер находится в `IDLE`,
но `cycle_count` сохраняет ранее заданное значение.

Повторный `resume()` начинает ту же последовательность с самого
начала. Счётчик завершённых циклов сбрасывается в ноль. Без этого
сброса повторная последовательность ошибочно завершилась бы после
одного цикла.

### Вызовы без эффекта

Функция ничего не делает, если указатель равен `NULL`, контроллер
не инициализирован, состояние уже `RUNNING` или последовательность
ещё не подготовлена (`cycle_count == 0`).

## Пауза: `led_controller_pause()`

~~~ c
void led_controller_pause(led_controller_t *controller);
~~~

Функция действует только в состоянии `RUNNING`.

Если активен fade, вызывается `fade_stop()`. Это сохраняет прогресс
перехода и не меняет текущую скважность PWM.

Если контроллер находится в фазе межцикловой паузы, fade не активен,
поэтому достаточно перевести контроллер в `PAUSED`.

Контроллер сохраняет текущую фазу. При последующем `resume()`
он определяет, как продолжить работу.

Повторный вызов pause, вызов в `IDLE` или вызов для
неинициализированного контроллера ничего не меняет.

## Обработка: `led_controller_process()`

~~~ c
bool led_controller_process(led_controller_t *controller);
~~~

Функция должна вызываться регулярно из основного цикла приложения
или другого периодического контекста.

Сначала она всегда вызывает:

~~~ c
soft_pwm_process(&controller->pwm);
~~~

Только после этого проверяет состояние контроллера и, если оно
равно `RUNNING`, обрабатывает текущую фазу.

Такой порядок принципиален: PWM должен продолжать формировать
последнее установленное значение яркости, даже если fade остановлен,
последовательность приостановлена или уже завершилась.

### Результат функции

- `false` --- последовательность ещё выполняется, контроллер
  не инициализирован или указатель равен `NULL`;
- `true` --- все запрошенные циклы завершены;
- при некорректном внутреннем значении фазы функция также возвращает
  `true` после безопасного выключения PWM и перевода контроллера
  в `IDLE`.

В штатном сценарии `true` возвращается один раз на завершение
последовательности. Следующие вызовы в `IDLE` вернут `false`.

### Почему PWM обрабатывается до проверки RUNNING

Пауза контроллера и пауза fade не означают остановку PWM.
Например, если светодиод находится на промежуточной скважности 35%,
после `led_controller_pause()` физический выход должен продолжать
переключаться с этой скважностью.

Если бы `soft_pwm_process()` вызывался только в состоянии
`RUNNING`, PWM перестал бы формировать фронты во время паузы.
Средняя яркость перестала бы поддерживаться.

Поэтому PWM обслуживается при каждом корректном вызове
`led_controller_process()`, независимо от состояния последовательности.

# Взаимодействие с нижележащими модулями

## Связь с fade

Контроллер использует один экземпляр `fade_t`.

При входе в fade-in вызывается:

~~~ c
fade_start(&controller->fade, 0, 100, fade_duration_ms);
~~~

При входе в fade-out:

~~~ c
fade_start(&controller->fade, 100, 0, fade_duration_ms);
~~~

В обоих случаях длительность берётся из
`controller->fade_duration_ms`.

Контроллер не рассчитывает промежуточную яркость. Он вызывает
`fade_process()` и проверяет состояние через
`fade_is_active()` и `fade_is_paused()`.

Переход считается завершённым, если fade одновременно не активен
и не приостановлен:

~~~ c
!fade_is_active(&controller->fade) &&
!fade_is_paused(&controller->fade)
~~~

Проверка обоих флагов нужна потому, что приостановленный fade тоже
не активен. Контроллер не должен принять паузу за завершение фазы.

## Связь с soft_pwm

Контроллер содержит собственный экземпляр `soft_pwm_t`.
В `fade_init()` передаётся указатель на него.

~~~ text
led_controller_process()
          |
          v
     fade_process()
          |
          v
  soft_pwm_set_duty()
          |
          v
  soft_pwm.on_time_us
          |
          v
  soft_pwm_process()
          |
          v
   output callback
~~~

В одной итерации контроллер сначала обслуживает PWM, а затем вызывает
`fade_process()`. Если fade установил новую скважность, она будет
использована при следующем обслуживании PWM с учётом текущей временной
фазы `soft_pwm`.

Контроллер не вызывает `soft_pwm_process()` из callback и не
переносит PWM-обработку в прерывание.

## Callback: pwm_led_output()

Функция `pwm_led_output()` связывает логический выход PWM
с выбранным светодиодом:

~~~ c
static void pwm_led_output(bool state, void *context);
~~~

Аргументы:

- `state` --- логическое состояние PWM;
- `context` --- указатель на экземпляр `led_controller_t`.

| `state` | Действие |
| --- | --- |
| `true` | `led_on(controller->led_idx)` |
| `false` | `led_off(controller->led_idx)` |

Индекс LED хранится в контексте контроллера. Callback всегда
воздействует на LED, который выбран последним успешным вызовом
`led_controller_prepare()`.

Callback выполняется синхронно из `soft_pwm`; это не обработчик
аппаратного прерывания.

## Переключение выбранного LED

При подготовке новой последовательности контроллер сначала
устанавливает PWM в 0%, пока `led_idx` ещё указывает на прежний LED.
Если физический выход был включён, callback выключает именно прежний
LED.

Только после этого контроллер меняет `led_idx` и явно выключает
новый LED. Такой порядок не позволяет команде выключения старого
светодиода попасть на новый после изменения индекса.

---

# Временная модель и SysTick

Контроллер использует SysTick для измерения межцикловой паузы.
Нижележащие `fade` и `soft_pwm` используют тот же общий счётчик.

## Владение инициализацией

`led_controller` не вызывает `nrfx_systick_init()`.

SysTick является глобальным аппаратным счётчиком, а не ресурсом
отдельного контроллера. Его инициализация принадлежит верхнему
уровню приложения (сейчас `main()`) и должна выполняться один раз
до инициализации потребителей времени.

Повторная инициализация из контроллера или нижележащих модулей
перезапускает общий счётчик и может нарушить временные отметки,
уже сохранённые другими экземплярами.

## Независимые интервалы

| Механизм | Назначение | Владелец |
| --- | --- | --- |
| PWM period | Частота переключения физического выхода | `soft_pwm` |
| Fade update interval | Частота изменения скважности | `fade` |
| Controller pause update interval | Шаг счётчика межцикловой паузы | `led_controller` |
| Fade duration | Число обработанных шагов fade | `fade` |
| Pause duration | Число обработанных шагов межцикловой паузы | `led_controller` |

Совпадение значений интервалов не означает общую временную константу.
Контроллер владеет своим интервалом межцикловой паузы, а `fade` ---
своим интервалом изменения скважности.

## Дискретная пауза контроллера

Межцикловая пауза измеряется не одним длинным таймаутом. Контроллер
проверяет короткий интервал SysTick, а после каждого истечения
увеличивает `pause_elapsed_ms` на
`LED_CONTROLLER_PAUSE_UPDATE_INTERVAL_MS`.

За один вызов `led_controller_process()` выполняется максимум один
шаг. Задержки основного цикла не компенсируются, поэтому реальная
пауза может быть длиннее заданной.

## Ограничение SysTick timeout

`pwm_period_us` передаётся в `soft_pwm_init()`, который использует
`nrfx_systick_test()` для определения окончания PWM-фаз. Период
должен находиться в допустимом диапазоне таймаута драйвера nrfx
для текущей частоты ядра.

Контроллер не дублирует проверку верхней границы периода.
Это предусловие API, как и в `soft_pwm`.

# Структура данных

`led_controller_t` объединяет состояние нижележащих модулей
и собственное состояние последовательности:

~~~ c
typedef struct {
    soft_pwm_t pwm;
    fade_t fade;

    nrfx_systick_state_t pause_start;

    uint32_t fade_duration_ms;
    uint32_t pause_duration_ms;
    uint32_t pause_elapsed_ms;

    uint32_t cycle_count;
    uint32_t cycles_completed;

    uint32_t led_idx;
    uint8_t phase;

    led_controller_state_t state;
    bool initialized;
} led_controller_t;
~~~

| Поле | Назначение |
| --- | --- |
| `pwm` | Экземпляр программного PWM |
| `fade` | Экземпляр линейного изменения скважности |
| `pause_start` | Временная отметка текущей межцикловой паузы |
| `fade_duration_ms` | Продолжительность fade-in и fade-out |
| `pause_duration_ms` | Требуемая длительность паузы между циклами |
| `pause_elapsed_ms` | Накопленное число шагов межцикловой паузы |
| `cycle_count` | Требуемое число полных циклов |
| `cycles_completed` | Число завершённых циклов текущей последовательности |
| `led_idx` | Логический индекс выбранного LED |
| `phase` | Внутренняя фаза последовательности |
| `state` | Публичное состояние контроллера |
| `initialized` | Признак успешной инициализации |

Структура содержит всё состояние экземпляра. Глобальных счётчиков
циклов или паузы нет, поэтому несколько контроллеров могут иметь
независимое состояние. При этом они используют общий SysTick и
обслуживаются вызывающим кодом.

Поля структуры доступны в C-заголовке, но являются состоянием
реализации. После инициализации ими следует управлять через публичные
функции, а не изменять напрямую.

---

# Публичный интерфейс

## `led_controller_init()`

Инициализирует экземпляр и возвращает `true` при успехе.
Возвращает `false`, если указатель равен `NULL` или инициализация
нижнего уровня `soft_pwm` не удалась.

Функция не подготавливает последовательность. После успешного
вызова требуется `led_controller_prepare()`.

## `led_controller_prepare()`

Подготавливает новую последовательность, выбирая LED и число циклов.
Некорректные аргументы игнорируются. Вызов заменяет предыдущую
последовательность и переводит контроллер в `IDLE`.

## `led_controller_pause()`

Приостанавливает только выполняющуюся последовательность.
Текущая яркость сохраняется, PWM продолжает обслуживаться.

## `led_controller_resume()`

Запускает подготовленную последовательность, продолжает
приостановленную или повторно запускает завершённую последовательность.
Первый вызов должен следовать за успешным `prepare()`.

## `led_controller_process()`

Обслуживает PWM и выполняет один шаг текущей фазы.
Возвращает `true` при завершении последовательности.

## `led_controller_is_running()`

Возвращает `true`, только если указатель корректен, экземпляр
инициализирован и состояние равно `RUNNING`.

# Ограничения и правила использования

## Регулярная обработка

Приложение должно регулярно вызывать `led_controller_process()`.
Этот вызов обслуживает fade, межцикловую паузу и PWM.

Редкие вызовы приводят к более медленному продвижению fade, увеличению
фактической межцикловой паузы и большему джиттеру фронтов PWM.
Контроллер не использует отдельные аппаратные таймеры для автоматического
вызова обработчиков.

## Последовательный доступ

Структура контроллера не защищена от конкурентного доступа.
`prepare()`, `pause()`, `resume()` и `process()` должны вызываться
последовательно из одного контекста либо с внешней синхронизацией.

Не следует одновременно изменять экземпляр из основного цикла
и обработчика прерывания без отдельной защиты.

## Инициализация светодиодов

`leds_init()` должна быть вызвана до `led_controller_init()`.
Во время инициализации PWM callback обращается к LED с индексом 0.

Количество светодиодов и допустимый диапазон индексов определяются
конфигурацией платы. В текущем интерфейсе `leds.h` предоставляет
`LEDS_NUMBER`, получаемый из конфигурации PCA10059.

## Подготовка перед запуском

Нельзя вызывать `resume()` как первый вызов после `init()`.
Сначала необходимо успешно вызвать `prepare()` с корректным
индексом LED и ненулевым числом циклов.

Проверка `cycle_count == 0` внутри `resume()` служит защитой
от ошибочной последовательности вызовов, а не заменяет контракт API.

## Нулевая длительность fade

Модуль `fade` поддерживает нулевую длительность как немедленное
применение целевого значения. Контроллер не запрещает
`fade_duration_ms == 0`.

В таком режиме fade-in и fade-out завершаются без промежуточных
значений. Последовательность всё равно проходит через обычную логику
фаз и счётчика циклов.

## Отсутствие компенсации задержек

Контроллер не компенсирует пропущенные вызовы
`led_controller_process()`. Он обрабатывает не более одного шага
fade или паузы за один вызов. Это polling-модель, согласованная
с текущими реализациями `fade` и `soft_pwm`.

# Итоговая модель

Контроллер является координатором, а не генератором яркости или PWM:

~~~ text
prepare(led, cycles)
        |
        v
      IDLE
        |
      resume()
        |
        v
     RUNNING
        |
        v
   +----------+
   | fade-in  |
   +----------+
        |
        v
   +----------+
   | fade-out |
   +----------+
        |
        v
   cycles complete?
      /       \\
    no         yes
    |           |
    v           v
  pause?       IDLE
  /   \\
 no    yes
 |      |
 |      v
 |    PAUSE
 |      |
 +-- next fade-in

pause() from RUNNING -> PAUSED
resume() from PAUSED -> RUNNING
prepare() from any state -> IDLE with new sequence
resume() from completed IDLE -> restart from cycle zero
~~~

Ключевые правила:

- `led_controller` управляет жизненным циклом последовательности;
- `fade` управляет изменением скважности;
- `soft_pwm` управляет временными ON/OFF-фазами;
- `leds` управляет физическими GPIO;
- SysTick инициализируется один раз на уровне приложения;
- PWM обслуживается даже тогда, когда последовательность не выполняет
  fade.
