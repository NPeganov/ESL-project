# soft_pwm

`soft_pwm` --- модуль программной генерации PWM-сигнала. Он формирует
логическое состояние выхода с заданными периодом и скважностью, используя
системный счётчик времени SysTick и регулярные вызовы
`soft_pwm_process()`.

Модуль не управляет GPIO напрямую. Физическое состояние выхода изменяется
через callback, переданный при инициализации. Благодаря этому
`soft_pwm` не зависит от конкретной платы и может использоваться для
управления любым выходом или другим программным объектом.

Модуль поддерживает:

- независимые экземпляры PWM;
- период в микросекундах;
- скважность от 0 до 100 процентов;
- немедленное переключение в постоянные состояния при 0 и 100 процентах;
- изменение скважности во время работы без принудительного сброса текущей
  PWM-фазы;
- минимальную длительность ненулевого импульса 1 мкс.

Формирование сигнала выполняется программно. Модуль не использует
аппаратный PWM-периферийный блок и не генерирует переключения самостоятельно
в прерывании таймера: вызывающий код должен регулярно вызывать
`soft_pwm_process()`.

---

# Место в архитектуре

В текущем приложении программный PWM используется как нижний механизм
управления яркостью светодиодов:

~~~ text
application
    |
    v
led_sequence
    |
    v
led_controller
    |
    +--------------------+
    |                    |
    v                    v
  fade                soft_pwm
    |                    |
    | set duty           | output callback
    +------------------->+
                         |
                         v
                  pwm_led_output()
                         |
                         v
                       leds
                         |
                         v
                        GPIO
                         |
                         v
                   physical LED
~~~

Распределение обязанностей:

- `fade` рассчитывает требуемую скважность во времени;
- `soft_pwm` преобразует скважность в последовательность логических
  состояний ON/OFF;
- callback связывает логическое состояние PWM с конкретным выходом;
- `leds` управляет физическим GPIO светодиода.

`soft_pwm` не знает о светодиодах, их индексах, цветах, яркости или
последовательностях мигания. Его задача --- только формирование PWM.

# Принцип работы

## Период и скважность

PWM-сигнал состоит из повторяющихся периодов. Каждый период включает:

- ON-фазу, когда выход находится в состоянии `true`;
- OFF-фазу, когда выход находится в состоянии `false`.

Скважность задаёт долю периода, в течение которой выход включён.

Для периода `T` и скважности `D`:

~~~ text
ON time  = T * D / 100
OFF time = T - ON time
~~~

Например, при периоде 1000 мкс:

| Скважность | ON time | OFF time |
| ---: | ---: | ---: |
| 0% | 0 мкс | постоянный OFF |
| 10% | 100 мкс | 900 мкс |
| 25% | 250 мкс | 750 мкс |
| 50% | 500 мкс | 500 мкс |
| 75% | 750 мкс | 250 мкс |
| 90% | 900 мкс | 100 мкс |
| 100% | постоянный ON | 0 мкс |

В реализации хранится длительность ON-фазы `on_time_us`. Длительность
OFF-фазы отдельно не вычисляется: она получается из полного периода и
прошедшего времени.

## Временная отметка фазы

Каждый экземпляр `soft_pwm_t` содержит собственную временную отметку
`phase_start`. Она задаёт начало текущего PWM-периода.

Для обычного промежуточного значения скважности временная схема выглядит
так:

~~~ text
phase_start
    |
    |<----------- ON time ----------->|
    |                                 |
    +---------------------------------+--------------------+
    |              ON                 |        OFF         |
    |                                 |                    |
    +---------------------------------+--------------------+
    |<------------------- period_us ---------------------->|
                                                          |
                                                   next period
~~~

Временная отметка обновляется только при переходе выхода в ON-состояние.
Поэтому начало OFF-фазы не становится началом нового периода.

Алгоритм использует одну временную отметку на весь период:

1. В состоянии ON модуль ожидает истечения `on_time_us` от
   `phase_start`.
2. После истечения ON-времени выход переключается в OFF.
3. В состоянии OFF модуль ожидает истечения полного `period_us` от
   той же `phase_start`.
4. После истечения периода выход переключается в ON, а `phase_start`
   обновляется текущим временем.
5. Начинается следующий период.

Таким образом, OFF-фаза заканчивается в момент, когда от начала периода
прошло полное `period_us`, а не через ещё один полный период после
выключения выхода.

## Почему временная отметка обновляется на переднем фронте

Период PWM отсчитывается от одного переднего фронта до следующего.
Поэтому временная отметка фиксируется при переходе OFF -> ON.

При переходе ON -> OFF временная отметка сохраняется. Это позволяет
определить конец периода относительно его начала.

Если бы отметка обновлялась также на заднем фронте, длительность OFF-фазы
ошибочно отсчитывалась бы от момента выключения и период сигнала стал бы
равен сумме ON-времени и полного OFF-таймаута.

# Изменение скважности

`soft_pwm_set_duty()` может вызываться как до начала генерации PWM, так
и во время работы модуля.

Поведение зависит от нового значения скважности.

## Переход к 0%

При установке скважности 0%:

1. `on_time_us` устанавливается в ноль;
2. выход немедленно переводится в OFF;
3. дальнейшие вызовы `soft_pwm_process()` не выполняют переключений.

Если выход уже был выключен, callback повторно не вызывается.

~~~ text
current output: ON or OFF
          |
          | set duty = 0%
          v
     constant OFF
~~~

## Переход к 100%

При установке скважности 100%:

1. `on_time_us` устанавливается равным `period_us`;
2. выход немедленно переводится в ON;
3. дальнейшие вызовы `soft_pwm_process()` не выполняют переключений.

Если выход уже был включён, callback повторно не вызывается.

~~~ text
current output: ON or OFF
          |
          | set duty = 100%
          v
     constant ON
~~~

Значения 0% и 100% являются постоянными состояниями, а не PWM с
нулевой или полной длительностью одной из фаз.

## Переход от постоянного состояния к промежуточной скважности

При переходе от 0% или 100% к значению между ними модуль начинает новую
PWM-фазу: `phase_start` устанавливается в момент вызова
`soft_pwm_set_duty()`.

Сам выход при этом не переключается. После перехода от 0% к промежуточной
скважности он остаётся выключенным до истечения первого полного периода.
Только после этого начинается первый ON-импульс.

Аналогично, после перехода от 100% к промежуточной скважности выход
остаётся включённым до обработки первого истечения ON-времени. Поскольку
новая временная отметка установлена при смене режима, первое выключение
произойдёт после соответствующего времени от начала новой фазы.

~~~ text
set intermediate duty
        |
        v
  phase_start = now
        |
        |<----------- period_us ----------->|
        |                                   |
 output remains OFF                        first ON
        +-----------------------------------+
~~~

## Изменение одной промежуточной скважности на другую

При изменении ненулевой промежуточной скважности текущая временная фаза
сохраняется. `phase_start` не сбрасывается.

Новое значение `on_time_us` начинает применяться относительно уже
существующего начала периода.

Это означает:

- если выход находится в ON и новая длительность ON уже истекла,
  следующий вызов `soft_pwm_process()` переключит выход в OFF;
- если выход находится в ON и новая длительность ON ещё не истекла,
  выход останется включённым до нового порога;
- если выход находится в OFF, он останется выключенным до завершения
  текущего полного периода;
- следующий передний фронт начнёт новый период с обновлённой скважностью.

Модуль не перезапускает период только потому, что изменилось значение
скважности.

~~~ text
                 duty changed here
                         |
                         v
phase_start              |
    |                    |
    |<---- old ON ------>|
    |<------ new ON ------------->|
    |                             |
    +-----------------------------+-------------------------+
    |             ON              |          OFF            |
    +-----------------------------+-------------------------+
    |<-------------------- same PWM period ---------------->|
~~~

Такое поведение исключает искусственный сброс временной фазы при каждом
обновлении скважности и является частью контракта модуля.

# Расчёт ON-времени

Для промежуточной скважности используется целочисленный расчёт:

~~~ c
pwm->on_time_us =
    ((uint64_t)pwm->period_us * duty_percent) /
    SOFT_PWM_PERCENT_MAX;
~~~

Промежуточное умножение выполняется в `uint64_t`, чтобы произведение
периода на скважность не переполняло 32-битный тип.

Деление выполняется целочисленно, поэтому дробная часть отбрасывается.
Например:

~~~ text
period_us  = 1000
duty       = 33%

on_time_us = 1000 * 33 / 100
           = 330 us
~~~

## Минимальная длительность импульса

Для ненулевой скважности результат целочисленного деления может оказаться
равным нулю. Например, при очень коротком периоде и малом проценте.

Модуль исправляет такой результат:

~~~ c
if (pwm->on_time_us == 0) pwm->on_time_us = 1;
~~~

Следовательно, любая ненулевая промежуточная скважность даёт как минимум
1 мкс ON-времени.

Разрешение расчёта составляет 1 мкс. При очень коротком периоде многие
значения скважности будут давать одинаковое ON-время. В частности,
при периоде 1 мкс любое ненулевое значение скважности округляется до
1 мкс и фактически становится постоянным ON-состоянием.

# Обработка PWM

## Роль `soft_pwm_process()`

Модуль не запускает отдельное прерывание для каждого фронта PWM.
Вместо этого вызывающий код регулярно вызывает:

~~~ c
soft_pwm_process(&pwm);
~~~

Функция проверяет, истёк ли таймаут текущей фазы. Если таймаут ещё не
истёк, она сразу возвращается. Если истёк, функция переключает выход.

Псевдокод алгоритма:

~~~ text
soft_pwm_process(pwm)
        |
        v
   pwm is NULL?
      /   \
    yes    no
     |      |
   return   v
       constant output?
          /   \
        yes    no
         |      |
       return   v
          select timeout:
          output ON  -> on_time_us
          output OFF -> period_us
                 |
                 v
        SysTick timeout expired?
              /   \
            no     yes
            |       |
          return    v
              toggle output
                    |
                    v
             output is ON?
                /   \
              yes    no
               |      |
        keep phase_start unchanged
          current time  keep phase_start
~~~

За один вызов `soft_pwm_process()` выполняется не более одного
переключения выхода. Функция не пытается воспроизвести все фронты,
которые могли быть пропущены, если вызывающий код долго не вызывал её.

## Частота вызова и точность

Поскольку PWM обслуживается опросом, момент переключения определяется
не только таймаутом SysTick, но и моментом ближайшего вызова
`soft_pwm_process()`.

Например, если ON-время истекло между двумя вызовами функции, выход
переключится при следующем вызове:

~~~ text
time -------------------------------------------------------->

ON timeout expires
        |
        v
        +-------------------------+
                                  |
                         next process() call
                                  |
                                  v
                             output OFF
~~~

Поэтому задержка фронта может достигать интервала между вызовами
`soft_pwm_process()`, не считая времени выполнения остального кода
основного цикла.

Для приемлемой формы сигнала вызывающий код должен:

- вызывать `soft_pwm_process()` регулярно;
- не выполнять длительные блокирующие операции между вызовами;
- учитывать, что частота основного цикла и его джиттер влияют на
  точность PWM.

Модуль не гарантирует аппаратную точность фронтов. Если приложению
понадобится точный PWM с минимальным джиттером, следует использовать
аппаратную PWM-периферию или другой механизм аппаратного таймирования.

## Пропущенные периоды

Если `soft_pwm_process()` вызывается слишком редко, таймаут может
истечь задолго до фактической обработки. Текущая реализация всё равно
выполнит только одно переключение.

Она не перемещает временную отметку на несколько периодов вперёд и
не генерирует серию быстрых переключений для компенсации пропуска.
После следующего переднего фронта новый период отсчитывается от
фактического времени этого переключения.

Это намеренное свойство простого polling-алгоритма.

# SysTick

`soft_pwm` использует функции Nordic nrfx:

~~~ c
nrfx_systick_get(&pwm->phase_start);
nrfx_systick_test(&pwm->phase_start, timeout_us);
~~~

`nrfx_systick_get()` сохраняет текущее значение свободно работающего
счётчика в структуру временной отметки.

`nrfx_systick_test()` проверяет, прошло ли заданное количество
микросекунд с момента сохранения отметки. Драйвер учитывает циклическое
переполнение счётчика SysTick.

## Инициализация SysTick

Сам `soft_pwm` не вызывает `nrfx_systick_init()`. Инициализация
общего системного счётчика является обязанностью более высокого уровня
приложения.

До вызова `soft_pwm_init()` приложение должно выполнить
`nrfx_systick_init()`.

Это общая зависимость не только `soft_pwm`, но и других модулей,
которые измеряют время через nrfx SysTick, например `fade`.

SysTick должен быть инициализирован один раз до начала работы таких
модулей. Повторная инициализация из каждого потребителя не требуется.

## Допустимый диапазон таймаута

Счётчик SysTick имеет ограниченную разрядность и периодически
переполняется. Драйвер nrfx ограничивает допустимый интервал одним
половинным диапазоном счётчика, чтобы однозначно определять истечение
таймаута.

Поэтому `period_us` должен укладываться в максимальный интервал,
поддерживаемый `nrfx_systick_test()` при текущей частоте ядра.

Для nRF52840 при частоте ядра 64 МГц максимальный интервал составляет
приблизительно 131 мс (точное допустимое значение определяется
макросами и расчётом в используемой версии nrfx).

Текущая реализация `soft_pwm_init()` проверяет только ненулевой период.
Она не дублирует проверку максимального таймаута драйвера. Передавать
период за пределами поддерживаемого диапазона нельзя: в Debug-сборке
nrfx может сработать assertion, а в Release-сборке вычисление времени
может стать неоднозначным.

# Публичный интерфейс

Заголовок `soft_pwm.h` предоставляет тип callback, структуру экземпляра,
максимальное значение скважности и три функции управления.

## Тип callback

~~~ c
typedef void (*soft_pwm_output_t)(bool state, void *context);
~~~

Callback сообщает вызывающему коду новое логическое состояние выхода:

- `true` --- выход включён (ON);
- `false` --- выход выключен (OFF).

`context` --- пользовательский указатель, переданный в
`soft_pwm_init()`. Модуль хранит его без интерпретации и передаёт
callback при каждом вызове.

Callback вызывается синхронно, непосредственно из той функции
`soft_pwm`, которая изменила состояние выхода. Он не вызывается из
отдельного таймерного прерывания.

Callback вызывается только при фактическом изменении состояния, кроме
инициализации: `soft_pwm_init()` вызывает его один раз с аргументом
`false` безусловно, чтобы привести физический выход в известное
начальное состояние.

Callback должен выполняться быстро и не блокировать обработку PWM на
длительное время.

## Структура `soft_pwm_t`

~~~ c
typedef struct
{
    uint32_t period_us;
    uint32_t on_time_us;
    nrfx_systick_state_t phase_start;
    bool output_state;
    soft_pwm_output_t output;
    void *output_context;
} soft_pwm_t;
~~~

Все поля принадлежат конкретному экземпляру:

| Поле | Назначение |
| --- | --- |
| `period_us` | Длительность полного PWM-периода в микросекундах |
| `on_time_us` | Длительность ON-фазы в микросекундах |
| `phase_start` | Временная отметка начала текущего периода |
| `output_state` | Последнее установленное логическое состояние выхода |
| `output` | Callback для передачи состояния наружу |
| `output_context` | Контекст, передаваемый callback |

Временная отметка находится внутри структуры, а не в статической
переменной реализации. Поэтому несколько экземпляров `soft_pwm_t`
могут иметь независимые периоды, скважности и временные фазы.

Поля структуры являются деталями реализации. После инициализации
вызывающий код должен менять скважность через `soft_pwm_set_duty()`,
а не напрямую изменять `on_time_us`, `phase_start` или
`output_state`.

## `soft_pwm_init()`

~~~ c
bool soft_pwm_init(
    soft_pwm_t *pwm,
    uint32_t period_us,
    soft_pwm_output_t output,
    void *output_context);
~~~

Инициализирует экземпляр программного PWM.

Параметры:

- `pwm` --- указатель на экземпляр, который требуется инициализировать;
- `period_us` --- период PWM в микросекундах;
- `output` --- callback логического состояния выхода;
- `output_context` --- пользовательский контекст callback.

Функция возвращает `false`, если:

- `pwm == NULL`;
- `period_us == 0`;
- `output == NULL`.

При успешной инициализации функция:

1. сохраняет период и callback;
2. устанавливает начальное ON-время в ноль;
3. устанавливает логическое состояние выхода в OFF;
4. сохраняет текущую временную отметку SysTick;
5. безусловно вызывает callback с `false`.

Таким образом, после успешного возврата экземпляр находится в
инициализированном состоянии с постоянным выключенным выходом.

Функция предполагает, что SysTick уже инициализирован и
`period_us` находится в допустимом для nrfx диапазоне.

До успешного вызова `soft_pwm_init()` нельзя вызывать остальные
функции модуля для этого экземпляра.

## `soft_pwm_set_duty()`

~~~ c
void soft_pwm_set_duty(
    soft_pwm_t *pwm,
    uint8_t duty_percent);
~~~

Устанавливает новую скважность PWM.

Параметры:

- `pwm` --- инициализированный экземпляр;
- `duty_percent` --- требуемая скважность в процентах.

Значение ограничивается диапазоном от 0 до
`SOFT_PWM_PERCENT_MAX`. Поскольку параметр имеет тип `uint8_t`,
значения от 101 до 255 будут ограничены до 100%.

Функция немедленно обрабатывает постоянные состояния 0% и 100%.
Для промежуточных значений рассчитывает `on_time_us` и оставляет
формирование последующих фронтов функции `soft_pwm_process()`.

При переходе из постоянного состояния к промежуточной скважности
устанавливается новая временная отметка. При изменении одной
промежуточной скважности на другую временная отметка сохраняется.

Передача `NULL` безопасно игнорируется. Функция не проверяет,
был ли экземпляр ранее успешно инициализирован.

## `soft_pwm_process()`

~~~ c
void soft_pwm_process(soft_pwm_t *pwm);
~~~

Обрабатывает текущее состояние PWM.

Функцию следует регулярно вызывать из основного цикла приложения
или другого периодически выполняемого контекста.

За один вызов функция может переключить выход не более одного раза.
При постоянном состоянии 0% или 100% она сразу возвращается.

Передача `NULL` безопасно игнорируется. Функция предполагает, что
экземпляр ранее успешно инициализирован.

# Ограничения и правила использования

## Последовательный доступ

Текущая реализация не защищает поля `soft_pwm_t` от конкурентного
доступа.

Вызовы `soft_pwm_set_duty()` и `soft_pwm_process()` должны
выполняться последовательно из одного контекста исполнения либо
с внешней синхронизацией.

Не следует одновременно вызывать эти функции из основного цикла
и обработчика прерывания без отдельной защиты.

## Время выполнения callback

Callback вызывается непосредственно из `soft_pwm_init()`,
`soft_pwm_set_duty()` или `soft_pwm_process()`. Поэтому длительный
callback увеличивает время выполнения соответствующего вызова и может
ухудшить точность последующих фронтов PWM.

Callback не должен блокировать выполнение на длительное время.

## Периодический вызов

После установки промежуточной скважности приложение обязано продолжать
вызывать `soft_pwm_process()`. Само по себе изменение скважности не
создаёт аппаратного события, которое позднее переключит выход.

## Инициализация экземпляра

Структуру `soft_pwm_t` не требуется предварительно обнулять вручную:
`soft_pwm_init()` записывает все поля, используемые модулем.

Однако все операции с экземпляром до успешной инициализации являются
ошибкой использования API.

## Несколько экземпляров

Каждый экземпляр хранит собственное состояние и временную отметку.
Поэтому один и тот же код может обслуживать несколько PWM-выходов:

~~~ c
soft_pwm_t pwm_a;
soft_pwm_t pwm_b;

soft_pwm_init(&pwm_a, 1000, output_a, context_a);
soft_pwm_init(&pwm_b, 2000, output_b, context_b);

soft_pwm_set_duty(&pwm_a, 25);
soft_pwm_set_duty(&pwm_b, 60);

while (1)
{
    soft_pwm_process(&pwm_a);
    soft_pwm_process(&pwm_b);
}
~~~

Оба экземпляра используют общий аппаратный SysTick как источник времени,
но имеют независимые временные отметки и параметры PWM.

# Граница ответственности

`soft_pwm` отвечает за:

- хранение параметров одного PWM-выхода;
- расчёт ON-времени по заданной скважности;
- отслеживание текущей временной фазы;
- переключение логического выхода при обработке истёкшего таймаута;
- вызов пользовательского callback при изменении состояния.

Модуль не отвечает за:

- инициализацию общего SysTick;
- настройку GPIO;
- выбор физического выхода;
- преобразование логического состояния в электрический уровень;
- расчёт плавного изменения яркости;
- частоту вызова `soft_pwm_process()`;
- синхронизацию конкурентных вызовов;
- восстановление пропущенных фронтов.

Эти обязанности принадлежат приложению или другим специализированным
модулям.

# Итоговая модель

Главная идея реализации --- один временной маркер на период и опрос
истечения соответствующей фазы:

~~~ text
                 phase_start
                      |
                      v
       +--------------+------------------+
       |                                 |
       | ON                              | OFF
       |                                 |
       | wait on_time_us                 | wait period_us
       |                                 |
       v                                 v
    output OFF                        output ON
       |                                 |
       | keep phase_start                | update phase_start
       |                                 |
       +---------------------------------+
                      |
                      v
                 next period
~~~

Постоянные состояния 0% и 100% обрабатываются немедленно и не требуют
периодического обслуживания. Для промежуточных значений PWM-фаза
сохраняется при изменении скважности, а очередное переключение
выполняется при ближайшем вызове `soft_pwm_process()` после истечения
соответствующего интервала.

Это простой polling-based механизм программного PWM с независимым
состоянием каждого экземпляра и явно определёнными временными
семантиками.
