# Модуль leds_pwm

## Назначение

`leds_pwm` — высокоуровневая, привязанная к плате PCA10059 абстракция управления жёлтым и RGB-светодиодами через аппаратный PWM.

Модуль предоставляет два способа задания цвета RGB-светодиода:

- RGB: три независимых 8-битных компонента;
- HSV: оттенок в градусах и насыщенность/яркость в процентах.

Отдельный API управляет яркостью жёлтого светодиода в процентах.

Модуль скрывает от вызывающего кода GPIO, PWM-каналы, активную полярность выходов, частоту PWM и преобразование цветовых пространств. Он не реализует мигание, временные последовательности или обработку пользовательского ввода.

## Место в архитектуре

```text
application
    |
    v
leds_pwm
    |
    +------> color
    |
    v
hardware/pwm
    |
    v
nRF52840 PWM0
    |
    v
LED GPIO pins
```

Файлы модуля:

| Файл | Ответственность |
|---|---|
| `leds_pwm.h` | Публичный API управления RGB и жёлтым LED |
| `leds_pwm.c` | Конфигурация платы, состояние LED и передача duty в PWM |
| `internal/color.h` | Внутренние типы RGB/HSV и объявления преобразований |
| `internal/color.c` | Целочисленное преобразование RGB/HSV и процентов в 8-битное значение |

`leds_pwm` использует универсальный аппаратный драйвер `pwm`. Модуль `color` является его внутренней вычислительной зависимостью и не обращается к периферии.

## Физические выходы и PWM-каналы

На PCA10059 используются четыре выхода:

| PWM-канал | GPIO из board header | Физический LED | Назначение |
|---|---|---|---|
| `PWM_CHANNEL_0` | `LED_1` | Жёлтый | Независимая яркость |
| `PWM_CHANNEL_1` | `LED_2` | Красный канал | RGB |
| `PWM_CHANNEL_2` | `LED_3` | Зелёный канал | RGB |
| `PWM_CHANNEL_3` | `LED_4` | Синий канал | RGB |

Все четыре выхода имеют активный низкий уровень. Это свойство задаётся в конфигурации PWM внутри `leds_pwm_init()`; вызывающему коду не нужно инвертировать значения.

Частота PWM фиксирована на уровне 1000 Гц. Она не является параметром публичного API.

## Инициализация

```c
bool leds_pwm_init(void);
```

Функция:

1. проверяет через `ASSERT`, что модуль ещё не инициализирован;
2. формирует конфигурацию аппаратного PWM на 1000 Гц;
3. назначает четыре GPIO и active-low полярность;
4. вызывает `pwm_init()`;
5. после успешного запуска PWM устанавливает внутреннее состояние RGB, HSV и жёлтой яркости в ноль.

Возвращает `false`, если нижележащий `pwm_init()` не смог выбрать тайминги или инициализировать nrfx-драйвер. При таком результате модуль не помечается как инициализированный.

После успешного вызова:

```text
yellow brightness = 0%
RGB                = (0, 0, 0)
HSV                = (0, 0%, 0%)
```

Все LED выключены.

Отдельный вызов `leds_gpio_init()` не требуется: GPIO выходы конфигурирует аппаратный PWM-драйвер на основании переданных номеров выводов. `leds_pwm` не вызывает функции `leds_gpio` для управления светодиодами.

Модуль рассчитан на однократную инициализацию. Повторный вызов нарушает предусловие и обнаруживается через `ASSERT`.

## RGB-интерфейс

```c
void leds_pwm_set_rgb(uint8_t red, uint8_t green, uint8_t blue);
void leds_pwm_get_rgb(uint8_t *red, uint8_t *green, uint8_t *blue);
```

Каждый компонент RGB находится в диапазоне 0…255:

| Компонент | Диапазон |
|---|---:|
| Red | 0…255 |
| Green | 0…255 |
| Blue | 0…255 |

Значения непосредственно соответствуют 8-битной шкале duty аппаратного PWM. Дополнительное масштабирование RGB-компонентов не выполняется.

При вызове `leds_pwm_set_rgb()` модуль:

1. сохраняет переданные значения в `m_rgb`;
2. преобразует их в HSV через `color_rgb_to_hsv()` и сохраняет результат в `m_hsv`;
3. передаёт три компонента в каналы `PWM_CHANNEL_1`, `PWM_CHANNEL_2` и `PWM_CHANNEL_3`.

RGB-светодиод выключен, когда все три компонента равны нулю.

`leds_pwm_get_rgb()` возвращает сохранённое RGB-представление. Все три указателя должны быть ненулевыми.

## HSV-интерфейс

```c
void leds_pwm_set_hsv(uint16_t hue, uint8_t saturation, uint8_t value);
void leds_pwm_get_hsv(uint16_t *hue, uint8_t *saturation, uint8_t *value);
```

Публичный диапазон HSV:

| Параметр | Диапазон | Единица |
|---|---:|---|
| Hue | 0…359 | градусы |
| Saturation | 0…100 | проценты |
| Value | 0…100 | проценты |

Перед преобразованием значения проверяются через `ASSERT`. Модуль не принимает hue = 360 и не ограничивает автоматически значения saturation/value.

При вызове `leds_pwm_set_hsv()` модуль:

1. сохраняет переданные HSV-компоненты в `m_hsv`;
2. преобразует HSV в RGB через `color_hsv_to_rgb()`;
3. сохраняет результат в `m_rgb`;
4. передаёт RGB-компоненты в три PWM-канала.

`leds_pwm_get_hsv()` возвращает сохранённое HSV-представление. Все три указателя должны быть ненулевыми.

### Согласованность двух представлений

Модуль хранит RGB и HSV одновременно. Setter обновляет представление, которое ему передали, и вычисляет второе:

- после `leds_pwm_set_rgb()` RGB getter возвращает исходные компоненты, HSV getter — результат RGB→HSV;
- после `leds_pwm_set_hsv()` HSV getter возвращает исходные параметры, RGB getter — результат HSV→RGB.

Поэтому getter возвращает последнее сохранённое представление, а не каждый раз заново вычисляет его из другого. Это важно учитывать при целочисленном преобразовании: RGB↔HSV не является абсолютно обратимой операцией из-за ограниченной точности и округления.

## Управление жёлтым LED

```c
void leds_pwm_set_yellow_brightness(uint8_t brightness);
uint8_t leds_pwm_get_yellow_brightness(void);
```

Яркость задаётся в диапазоне 0…100 процентов:

- 0% — выключен;
- 100% — максимальная яркость;
- промежуточные значения задают соответствующую долю активного времени PWM.

Setter проверяет диапазон через `ASSERT`, сохраняет процент в `m_yellow_brightness`, переводит его в 8-битную шкалу функцией `color_percent_to_value()` и обновляет `PWM_CHANNEL_0`.

Преобразование выполняется с округлением к ближайшему целому:

```c
value = (percent * 255 + 50) / 100;
```

Getter возвращает сохранённое процентное значение, а не пересчитанное обратно значение PWM duty.

Жёлтый LED не связан с RGB-состоянием: изменение RGB/HSV не влияет на его яркость, и наоборот.

## Внутреннее состояние

`leds_pwm.c` хранит:

| Переменная | Назначение |
|---|---|
| `m_initialized` | Признак успешной инициализации |
| `m_rgb` | Текущее RGB-представление цвета |
| `m_hsv` | Текущее HSV-представление цвета |
| `m_yellow_brightness` | Последняя заданная яркость жёлтого LED в процентах |

Состояние статическое и принадлежит единственному экземпляру модуля. API не принимает указатель на объект и не поддерживает несколько независимых наборов LED.

## Временное поведение и ограничения

В `leds_pwm` нет таймера, периодического обработчика или функции `process()`. Setter изменяет запрошенные выходные значения, а аппаратный PWM продолжает формировать сигнал независимо от основного цикла приложения.

Модуль намеренно не реализует:

- мигание и задержки;
- плавные переходы яркости;
- последовательности цветов;
- обработку кнопки или режимы приложения;
- остановку и повторную настройку PWM;
- изменение частоты PWM после инициализации.

Эти задачи принадлежат вызывающему коду или отдельным верхнеуровневым модулям.

## Проверки предусловий

Публичные функции требуют успешного вызова `leds_pwm_init()`.

Через `ASSERT` проверяются:

- повторная инициализация;
- вызовы setter/getter до инициализации;
- hue вне диапазона 0…359;
- saturation/value/brightness больше 100;
- нулевые указатели getter-функций.

Setter-функции не возвращают статус. Некорректное использование API рассматривается как нарушение предусловий, а не как штатная ошибка выполнения.

## Зависимости

`leds_pwm` зависит от:

- board header `pca10059.h` — определения LED GPIO;
- `hardware/pwm/pwm.h` — универсальный аппаратный PWM API;
- `internal/color.h` — RGB/HSV и процентные преобразования;
- Nordic `ASSERT` — проверка предусловий.

Для подробностей аппаратного уровня см. [документацию PWM](../hardware/pwm/pwm.md), а алгоритмы преобразования описаны в [документации color](internal/color.md).
