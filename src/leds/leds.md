# leds

`leds` --- низкоуровневый модуль управления физическими светодиодами
платы. Он предоставляет приложению простой интерфейс, в котором
светодиоды адресуются логическими индексами, а детали GPIO и
особенности конкретной платы остаются внутри реализации.

Модуль умеет:

- настраивать GPIO всех светодиодов как выходы;
- включать один светодиод;
- выключать один светодиод;
- выключать все светодиоды.

`leds` не управляет яркостью, не формирует PWM и не задаёт
последовательности мигания. Это задачи расположенных выше модулей.

## Общая схема

~~~ text
        application
             │
             │ led_on(index)
             │ led_off(index)
             │ leds_off()
             │ leds_init()
             ▼
          leds.h
             │
             ▼
          leds.c
             │
             ├── logical LED index
             │
             ▼
       m_led_list[index]
             │
             ▼
          GPIO pin
             │
             ▼
       physical LED
~~~

Внешний код работает с индексами светодиодов. Сопоставление индекса
с конкретным GPIO выполняется внутри `leds.c` на основании
конфигурации платы.

---

# Конфигурация платы

Текущая сборка проекта предназначена для платы PCA10059.

Её конфигурация задаётся заголовком Nordic SDK:

~~~ c
pca10059.h
~~~

В нём определены:

~~~ c
#define LEDS_NUMBER 4

#define LED_1 LED1_G
#define LED_2 LED2_R
#define LED_3 LED2_G
#define LED_4 LED2_B

#define LEDS_ACTIVE_STATE 0

#define LEDS_LIST { LED_1, LED_2, LED_3, LED_4 }
~~~

Для PCA10059 доступны четыре логических светодиода: отдельный
зелёный светодиод LED1 и три цветовых канала RGB-светодиода LED2.
Каждый канал RGB-светодиода рассматривается как отдельный логический
светодиод:

| Логический индекс | Обозначение SDK | Цвет | GPIO |
| ---: | --- | --- | --- |
| 0 | `LED_1` / `LED1_G` | зелёный LED1 | P0.06 |
| 1 | `LED_2` / `LED2_R` | красный LED2 | P0.08 |
| 2 | `LED_3` / `LED2_G` | зелёный LED2 | P1.09 |
| 3 | `LED_4` / `LED2_B` | синий LED2 | P0.12 |

Таким образом, индекс в публичном API не является номером GPIO.
Например, индекс `2` обозначает зелёный канал RGB-светодиода LED2,
подключённый к GPIO P1.09.

## Таблица соответствия индексов и GPIO

В `leds.c` находится приватный массив:

~~~ c
static const uint8_t m_led_list[LEDS_NUMBER] = LEDS_LIST;
~~~

После препроцессора для текущей платы он содержит GPIO-пины в том же
порядке, что и логические индексы:

~~~ text
index       m_led_list[index]       physical output
  0    ──►  LED_1 / P0.06      ──►  green LED1
  1    ──►  LED_2 / P0.08      ──►  red LED2
  2    ──►  LED_3 / P1.09      ──►  green LED2
  3    ──►  LED_4 / P0.12      ──►  blue LED2
~~~

Массив имеет внутреннее связывание (`static`) и не объявляется в
`leds.h`. Поэтому таблица соответствия существует только в одной
копии --- внутри реализации модуля.

Это также означает, что остальной код не должен самостоятельно
обращаться к `m_led_list` или знать номера GPIO.

# Активный уровень

Светодиоды PCA10059 подключены по схеме active-low.

Для них в конфигурации платы задано:

~~~ c
#define LEDS_ACTIVE_STATE 0
~~~

Следовательно:

~~~ text
GPIO = 0  → LED включён
GPIO = 1  → LED выключен
~~~

Модуль не заставляет вызывающий код учитывать эту особенность.
Функция `led_on()` всегда включает светодиод, а `led_off()` всегда
выключает его.

Преобразование логического состояния в электрический уровень
выполняется внутри `leds.c`:

~~~ c
// LED on
nrf_gpio_pin_write(pin, LEDS_ACTIVE_STATE);

// LED off
nrf_gpio_pin_write(pin, !LEDS_ACTIVE_STATE);
~~~

Таким образом, при изменении платы или её электрической схемы
публичный интерфейс может остаться прежним: достаточно корректно
задать `LEDS_LIST`, `LEDS_NUMBER` и `LEDS_ACTIVE_STATE` в
конфигурации платы.

# Публичный интерфейс

Заголовок `leds.h` содержит только функции, доступные внешнему коду:

~~~ c
void led_on(uint32_t led_idx);
void led_off(uint32_t led_idx);
void leds_off(void);
void leds_init(void);
~~~

Для индекса используется `uint32_t`, как и в аналогичном API
Nordic SDK `bsp_board_led_on()` / `bsp_board_led_off()`.

Допустимые индексы начинаются с нуля и заканчиваются
`LEDS_NUMBER - 1`.

## `leds_init()`

Инициализирует GPIO всех светодиодов.

Сначала каждый соответствующий GPIO настраивается как выход:

~~~ c
nrf_gpio_cfg_output(m_led_list[led_idx]);
~~~

После настройки всех выходов вызывается `leds_off()`.

Полная последовательность:

~~~ text
leds_init()
    │
    ├── configure GPIO for LED 0 as output
    ├── configure GPIO for LED 1 as output
    ├── configure GPIO for LED 2 as output
    ├── configure GPIO for LED 3 as output
    │
    ▼
leds_off()
    │
    ├── led_off(0)
    ├── led_off(1)
    ├── led_off(2)
    └── led_off(3)
~~~

После завершения `leds_init()` все светодиоды находятся в выключенном
состоянии.

Функция не возвращает статус: настройка GPIO выполняется средствами
Nordic HAL, а отдельная обработка ошибок в текущей реализации не
предусмотрена.

Инициализацию следует выполнить до вызова остальных функций модуля,
поскольку именно она настраивает используемые GPIO как выходы.

## `led_on(uint32_t led_idx)`

Включает светодиод с указанным логическим индексом.

~~~ c
led_on(0);
~~~

Для PCA10059 этот вызов включает отдельный зелёный светодиод LED1,
то есть GPIO P0.06.

Внутри функция:

1. проверяет индекс через `ASSERT(led_idx < LEDS_NUMBER)`;
2. получает GPIO из `m_led_list[led_idx]`;
3. записывает на GPIO активный уровень `LEDS_ACTIVE_STATE`.

Функция не меняет состояние других светодиодов.

## `led_off(uint32_t led_idx)`

Выключает светодиод с указанным логическим индексом.

~~~ c
led_off(0);
~~~

Внутри функция выполняет те же действия, что и `led_on()`, но
записывает неактивный уровень:

~~~ c
!LEDS_ACTIVE_STATE
~~~

Для PCA10059 это логическая единица.

Функция не меняет состояние других светодиодов.

## `leds_off()`

Выключает все светодиоды платы.

~~~ c
leds_off();
~~~

Функция проходит по всем допустимым индексам и для каждого вызывает
`led_off()`:

~~~ c
for (uint32_t led_idx = 0; led_idx < LEDS_NUMBER; led_idx++)
    led_off(led_idx);
~~~

Отдельная реализация управления GPIO здесь не нужна: общий механизм
выключения одного светодиода уже находится в `led_off()`.

Функция может использоваться как после инициализации GPIO, так и
позднее, когда требуется погасить все светодиоды.

# Проверка индекса

В `led_on()` и `led_off()` используется:

~~~ c
ASSERT(led_idx < LEDS_NUMBER);
~~~

Это диагностическая проверка Nordic SDK.

При включённой конфигурации assertions она обнаруживает выход индекса
за допустимый диапазон. В Release-сборке без соответствующих
`DEBUG_NRF` / `DEBUG_NRF_USER` проверка может быть отключена.

Поэтому вызывающий код обязан передавать корректный индекс независимо
от конфигурации сборки.

Передача индекса вне диапазона не является поддерживаемым способом
вызова API: после отключённой проверки обращение к
`m_led_list[led_idx]` приведёт к выходу за границы массива.

# Взаимодействие с остальными модулями

`leds` является нижним уровнем управления физическими выходами.
Он не знает, почему и на какое время требуется включить светодиод.

Например, `led_controller` использует callback программного PWM,
чтобы преобразовать логическое состояние PWM в вызовы `led_on()`
и `led_off()`:

~~~ text
led_controller
      │
      ▼
soft_pwm
      │
      │ output(state, context)
      ▼
pwm_led_output()
      │
      ├── state == true  → led_on(led_idx)
      │
      └── state == false → led_off(led_idx)
                               │
                               ▼
                              GPIO
                               │
                               ▼
                         physical LED
~~~

В этой схеме обязанности разделены:

- `soft_pwm` формирует логическое состояние PWM;
- callback `pwm_led_output()` связывает это состояние с выбранным
  светодиодом;
- `leds` преобразует логический индекс в GPIO и устанавливает
  физический уровень.

Сам модуль `leds` ничего не знает о периоде PWM, скважности,
плавном изменении яркости, количестве миганий или паузах.

---

# Граница ответственности

Модуль `leds` отвечает только за непосредственное управление GPIO
светодиодов:

~~~ text
logical LED index
       │
       ▼
   leds_on/off
       │
       ▼
  index-to-GPIO map
       │
       ▼
  GPIO output level
       │
       ▼
  physical LED state
~~~

Он не отвечает за:

- программный PWM;
- регулировку яркости;
- плавное включение и выключение;
- последовательности мигания;
- выбор светодиода по идентификатору устройства;
- паузы между циклами или между разными светодиодами;
- обработку событий кнопки.

Эти задачи находятся на более высоких уровнях приложения.

Такое разделение позволяет использовать `leds` как небольшой
аппаратно-зависимый слой, не связывая остальной код с конкретными
GPIO и active-low особенностями платы.
