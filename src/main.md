# main — сквозное описание приложения

## Назначение

`main.c` — точка входа и верхнеуровневый координатор запуска. Сам файл намеренно мал: он инициализирует логирование, запускает HSV Picker и затем обслуживает отложенные сообщения в основном цикле.

Этот документ описывает не только `main()`, но и всё приложение сверху донизу: пользовательское поведение, архитектурные слои, порядок инициализации, движение событий и данных, временную обработку и физическое управление светодиодами.

## Назначение устройства

Приложение реализует HSV color picker на nRF52840 и плате PCA10059. На плате используются четыре светодиодных выхода:

- отдельный жёлтый LED — показывает выбранный режим;
- красный, зелёный и синий каналы RGB LED — отображают выбранный цвет.

Одна кнопка управляет выбором HSV-компонента и его изменением.

HSV использует следующие диапазоны:

| Компонент | Диапазон |
|---|---:|
| Hue (H) | 0…359 градусов |
| Saturation (S) | 0…100% |
| Value (V) | 0…100% |

## Архитектура сверху вниз

```text
main
 ├── log
 └── hsv_picker
      ├── nvm_log
      │    └── Application Data Area flash page
      ├── timer_service
      │    └── LFCLK / app_timer
      ├── btn
      │    └── btn_hw
      │         └── GPIO / GPIOTE / debounce timer
      └── leds_control
           ├── leds_control_hsv
           ├── leds_control_yellow
           └── leds_pwm
                ├── internal/color
                └── hardware/pwm
                     └── nRF52840 PWM0
                          └── LED GPIO pins
```

Ответственность разделена по слоям:

1. **main** — порядок запуска и основной цикл.
2. **hsv_picker** — пользовательские режимы, реакция на события кнопки, восстановление/сохранение HSV, начальный цвет и прикладное логирование.
3. **nvm_log** — одностраничный журнал 32-битных записей в Application Data Area flash.
4. **btn** — преобразование подтверждённых состояний кнопки в логические события.
5. **btn_hw** — обнаружение GPIO-фронтов и подтверждение стабильного состояния после debounce.
6. **leds_control** — фасад управления LED, два контроллера поведения и общий периодический таймер.
7. **leds_control_hsv / leds_control_yellow** — временные алгоритмы изменения HSV и индикации жёлтого LED.
8. **leds_pwm** — привязка LED к PWM-каналам, кэширование RGB/HSV и яркости жёлтого LED.
9. **color** — целочисленные преобразования цветовых представлений.
10. **hardware/pwm** — универсальный драйвер периферии PWM.
11. **timer_service** — общая подготовка LFCLK и app_timer.
12. **log** — обёртка над Nordic logger и USB CDC ACM backend.

`leds_gpio` — отдельный низкоуровневый GPIO-драйвер. Он не является частью цепочки `leds_pwm → hardware/pwm` и в текущем HSV Picker не используется.

## Запуск приложения

Точка входа выполняет:

```c
int main(void) {
    log_init();

    if (!hsv_picker_init())
        APP_ERROR_HANDLER(NRF_ERROR_INTERNAL);

    hsv_picker_start();

    while (true) {
        hsv_picker_process();
        log_process();
        __WFE();
    }
}
```

Порядок принципиален:

1. `log_init()` настраивает Nordic logger и USB logging backend.
2. `hsv_picker_init()` инициализирует прикладные зависимости и подготавливает начальный цвет.
3. `hsv_picker_start()` включает обработку кнопки.
4. Основной цикл вызывает `hsv_picker_process()` для выполнения отложенной записи HSV во flash.
5. Затем `log_process()` обрабатывает отложенные сообщения и `__WFE()` переводит CPU в ожидание события.

Периодические обновления LED и обработка кнопки выполняются асинхронно через app_timer/GPIOTE. Основной цикл не опрашивает кнопку и не рассчитывает яркость светодиодов.

Если инициализация HSV Picker завершается ошибкой, приложение передаёт `NRF_ERROR_INTERNAL` в `APP_ERROR_HANDLER`; штатный пользовательский цикл не запускается.

## Инициализация снизу вверх

Вызов `hsv_picker_init()` выполняет следующую последовательность:

```text
hsv_picker_init()
   |
   +--> nvm_log_init(HSV_FREE_VALUE_MASK)
   |      +--> scan the first Application Data Area page
   |      +--> locate the most recent consecutive record
   |
   +--> timer_service_init()
   |      +--> initialize shared clock driver if needed
   |      +--> request and wait for LFCLK
   |      +--> app_timer_init()
   |
   +--> lc_init()
   |      +--> leds_pwm_init()
   |      |      +--> configure four active-low PWM channels
   |      |      +--> pwm_init()
   |      +--> set yellow brightness to 0%
   |      +--> hsv_init()
   |      +--> yellow_init()
   |      +--> create and start 10 ms control timer
   |
   +--> set application mode to NO_INPUT
   +--> load and validate the saved HSV value
   |      +--> restore it when valid
   |      +--> otherwise derive the default from DEVICE_ID
   +--> btn_init(button_event_handler)
          +--> btn_hw_init(button_state_changed)
          |      +--> create debounce timer
          |      +--> initialize/reuse GPIOTE
          |      +--> configure button input
          +--> create double-press timer
```

Затем `hsv_picker_start()` устанавливает жёлтый LED в OFF и вызывает `btn_start()`. Аппаратный уровень включает GPIOTE events и запускает debounce первоначального физического состояния кнопки.

Разделение init/start означает, что драйверы и начальное состояние подготавливаются до того, как приложение начнёт принимать пользовательский ввод.

### Владение таймерами

| Таймер | Владелец | Назначение |
|---|---|---|
| Общий repeated app_timer, 10 мс | `leds_control` | Вызывает оба LED-контроллера |
| Debounce one-shot app_timer | `btn_hw` | Подтверждает стабильность входа кнопки |
| Double-press one-shot app_timer | `btn` | Завершает окно ожидания второго нажатия |

`timer_service` не создаёт прикладные таймеры. Он один раз подготавливает clock infrastructure и app_timer до создания таймеров зависимыми модулями.

## Пользовательское поведение

### Режимы

Двойное нажатие переключает режим по циклу:

```text
NO_INPUT → HUE → SATURATION → BRIGHTNESS → NO_INPUT
```

| Режим | HSV-компонент | Жёлтый LED |
|---|---|---|
| `MODE_NO_INPUT` | Не изменяется | Выключен |
| `MODE_HUE` | Hue | Медленное плавное мигание |
| `MODE_SATURATION` | Saturation | Быстрое плавное мигание |
| `MODE_BRIGHTNESS` | Value | Постоянно включён |

В логах режим Value называется `BRIGHTNESS`, хотя внутренний HSV-компонент называется `LC_VALUE`.

В режиме `NO_INPUT` нажатие и удержание не запускает изменение цвета.

### Нажатие и отпускание

- `BTN_EVENT_PRESS`: если выбран H/S/V и изменение ещё не активно, `hsv_picker` вызывает `lc_start_hsv_change()`.
- `BTN_EVENT_RELEASE`: если изменение было запущено, вызывается `lc_stop_hsv_change()`; прогресс сохраняется.
- `BTN_EVENT_SINGLE_PRESS`: приложение игнорирует это событие.
- `BTN_EVENT_DOUBLE_PRESS`: переключает режим и соответствующую индикацию.

Событие `DOUBLE_PRESS` приходит после второго подтверждённого отпускания. Поэтому второе отпускание сначала обрабатывается как `RELEASE` и приостанавливает изменение прежнего компонента; затем отдельное событие `DOUBLE_PRESS` выбирает следующий режим.

### Начальный цвет

При запуске `hsv_picker` сначала пытается восстановить последнее корректное HSV-значение из flash. Если запись отсутствует или её компоненты выходят за допустимые диапазоны, используется значение по `DEVICE_ID`.

В `hsv_picker.c` задан `DEVICE_ID = "6609"`. Последние две цифры трактуются как процент полного круга Hue:

```c
hue = percent * 360 / 100;
```

Целочисленное деление отбрасывает дробную часть. Для ID `6609` процент равен 9, поэтому начальный цвет:

- H = 32°;
- S = 100%;
- V = 100%.

Полученное значение по `DEVICE_ID` используется только как начальное состояние при отсутствии корректной сохранённой записи; успешное восстановление из памяти имеет приоритет. Жёлтый LED при старте выключен.

## Как кнопка превращается в событие приложения

### Аппаратный уровень: btn_hw

`btn_hw` настраивает вход кнопки PCA10059 и GPIOTE. Каждый GPIO-фронт сохраняет новое наблюдаемое состояние и перезапускает one-shot debounce timer. После интервала 10 мс физический вход читается повторно:

- если уровень отличается от последнего кандидата, кандидат обновляется и начинается новый интервал;
- если уровень стабилен, он становится подтверждённым и передаётся в `btn`.

Первое подтверждённое состояние после `btn_start()` только инициализирует логическое состояние кнопки. Оно не генерирует пользовательское событие. Это корректно обрабатывает и случай, когда кнопка уже удерживается во время запуска.

### Логический уровень: btn

`btn` получает только `bool pressed`; он не знает GPIO и debounce. При последующих изменениях он формирует события:

- при подтверждённом нажатии — `BTN_EVENT_PRESS`;
- при подтверждённом отпускании — `BTN_EVENT_RELEASE`;
- после каждого завершённого цикла press→release — `BTN_EVENT_SINGLE_PRESS`;
- если второй завершённый цикл укладывается в 1000 мс от первого подтверждённого отпускания — дополнительно `BTN_EVENT_DOUBLE_PRESS`.

Таким образом, двойное нажатие распознаётся по времени между двумя завершёнными циклами, а не только по двум фронтам нажатия. При втором отпускании сначала отправляется `RELEASE`, затем `SINGLE_PRESS`, затем `DOUBLE_PRESS`.

Callback зарегистрированного приложения вызывается из цепочки обработки кнопки. Он должен оставаться коротким. Логирование настроено в deferred-режиме, а фактическая обработка сообщений выполняется в основном цикле через `log_process()`.

## Как изменение HSV доходит до RGB LED

### Координатор leds_control

`hsv_picker` не обращается к PWM. Он вызывает публичные функции `leds_control`.

`lc_init()` инициализирует `leds_pwm`, сбрасывает два контроллера и запускает один repeated timer с периодом 10 мс. Каждый callback один раз считывает `app_timer_cnt_get()` и передаёт одинаковый timestamp в:

```c
hsv_process(now);
yellow_process(now);
```

Контроллеры не создают собственные таймеры. Они вычисляют требуемое состояние и обращаются к `leds_pwm`.

### Алгоритм HSV

`leds_control_hsv` изменяет только один компонент за раз.

- Hue совершает полный оборот за 10 секунд в направлении увеличения угла, затем циклически возвращается к началу.
- Saturation движется по треугольной волне между 0 и 100%; полупериод — 5 секунд.
- Value использует такую же треугольную волну и собственную константу полупериода 5 секунд.

Каждый новый запуск начинается от текущего значения выбранного компонента. Повторный запуск того же активного компонента не сбрасывает прогресс. После отпускания изменение приостанавливается; повторный запуск того же компонента продолжает с сохранённой фазой, не учитывая время паузы. При выборе другого компонента предыдущий интервал сначала доводится до текущего момента, затем новый компонент начинает собственный цикл от своего текущего значения.

Вычисления основаны на суммарном активном времени, а не на последовательном прибавлении к предыдущему результату. Это уменьшает накопление дрейфа из-за задержек callback. Для Hue используется modulo 360; Saturation и Value отражаются на границах диапазона.

### Жёлтая индикация

`leds_control_yellow` независимо управляет яркостью отдельного жёлтого LED:

| Паттерн | Fade in | Hold on | Fade out | Hold off | Полный цикл |
|---|---:|---:|---:|---:|---:|
| Slow | 1000 мс | 200 мс | 1000 мс | 200 мс | 2400 мс |
| Fast | 150 мс | 50 мс | 150 мс | 50 мс | 400 мс |

Переходы яркости линейные. При выборе мигающего паттерна цикл начинается с нулевой яркости. Расчёт использует время от начала паттерна по modulo длины цикла, поэтому задержка периодического callback не сдвигает фазу накапливающимся образом. Для OFF устанавливается 0%, для ON — 100%.

RGB и жёлтая индикация независимы: смена режима не меняет цвет RGB, а изменение HSV не меняет паттерн жёлтого LED.

## От leds_pwm к аппаратному PWM

`leds_pwm` — аппаратно-зависимый LED-слой для PCA10059. Он назначает PWM-каналы:

| PWM channel | Выход платы | Назначение |
|---|---|---|
| 0 | LED_1 | Жёлтый LED |
| 1 | LED_2 | Красный канал |
| 2 | LED_3 | Зелёный канал |
| 3 | LED_4 | Синий канал |

Все выходы настроены как active-low. Логическое значение яркости остаётся одинаковым для вызывающего кода: 0 — выключено, максимум — включено; инверсия скрыта внутри PWM-драйвера.

Для RGB модуль хранит последние RGB и HSV представления. При установке HSV выполняется преобразование HSV→RGB, после чего три канала передаются в `pwm_set()`. При установке RGB выполняется обратное преобразование. Getter возвращает кэшированное представление, а не повторно измеряет физический выход. Жёлтая яркость хранится отдельно в процентах.

`color` выполняет целочисленное преобразование между HSV (H в градусах, S/V в процентах) и RGB (0…255 на канал), а также переводит процент яркости в 8-битное значение. Модуль не обращается к периферии.

### hardware/pwm

Универсальный `hardware/pwm` использует PWM0 nRF52840 и четыре независимых канала. Частота фиксирована внутри драйвера: база 1 МГц, выходная частота 1 кГц, TOP = 999. Логический duty передаётся в диапазоне 0…255.

`pwm_init()` настраивает периферию и запускает циклическое воспроизведение одной логической sequence. `nrfx_pwm_simple_playback()` использует оба аппаратных sequence slot для loop; приложение хранит один sequence buffer и сигнализирует оба события окончания sequence. Новые duty значения копируются в буфер обработчиком примерно с интервалом 10 мс. PWM продолжает формировать выход независимо от main loop.

PWM не знает о назначении каналов как yellow/red/green/blue. Это знание принадлежит `leds_pwm`.

## Отдельный leds_gpio

`hardware/leds_gpio` предоставляет прямые функции GPIO on/off по индексу. Это самостоятельный драйвер для простого цифрового управления. Он не является зависимостью `leds_pwm`, не выполняет PWM и не используется текущим HSV Picker.

## Постоянное хранение HSV

Прикладной слой сериализует HSV в одно 32-битное слово: H занимает биты 0…15, S — 16…23, V — 24…31. При инициализации `hsv_picker` передаёт `nvm_log_init()` маску, позволяющую отличить стёртую ячейку от любого допустимого HSV payload. Сам `nvm_log` не знает семантики HSV и не проверяет диапазоны компонентов.

`nvm_log` использует первую страницу Application Data Area по адресу `0xDD000` (4096 байт, 1024 слова). Записи размещаются последовательно по одному 32-битному слову. При старте модуль сканирует последовательность до первой свободной ячейки; `nvm_log_load()` возвращает последнюю занятую запись. Если страница заполнена, перед следующей записью она стирается целиком, после чего новая запись помещается в начало. Поэтому журнал хранит историю только до заполнения страницы, а затем начинает её заново; отдельного commit marker или wear-leveling нет.

Запись выполняется из `hsv_picker_process()`, а не из callback кнопки. Когда пользователь завершает цикл выбора параметров и возвращается в `NO_INPUT`, обработчик устанавливает флаг отложенного сохранения. Основной цикл забирает этот запрос и вызывает `nvm_log_save()`. Сообщение `Saved HSV color` выводится только после успешного завершения записи. При старте логируются либо восстановленные H/S/V, либо сформированное из `DEVICE_ID` начальное состояние.

Подробности формата, сканирования, ограничений и NVMC-взаимодействия приведены в [документации nvm_log](nvm_log/nvm_log.md).

## Логирование и основной цикл

`log` — тонкая обёртка над Nordic logger и USB CDC ACM backend. В конфигурации включён deferred logging. Вызовы `LOG_INFO` и `LOG_ERROR` помещают сообщения в очередь; передача и обработка USB/backend выполняется через `log_process()` из основного цикла.

Основной цикл не занят ожиданием таймера и не опрашивает аппаратные входы. После обработки доступных логов `__WFE()` переводит CPU в ожидание события. Аппаратные события, таймеры и периферия продолжают обслуживаться независимо.

## Ошибки и ограничения

- Ошибка инициализации timer service, LED control или PWM приводит к отказу `hsv_picker_init()`; `main` передаёт ошибку в `APP_ERROR_HANDLER`.
- Ошибка создания или запуска общего control timer приводит к `false` из `lc_init()`.
- `btn_init()` и `btn_start()` используют Nordic error/assert механизм для ошибок конфигурации и таймеров.
- PWM частота и период обновления фиксированы внутри `hardware/pwm`; публичного API изменения частоты нет.
- Приложение поддерживает один экземпляр каждого статического модуля.
- `leds_gpio` не участвует в управлении PWM LED.
- В текущем приложении нет отдельной очереди прикладных режимов: двойное нажатие переключает режим сразу в callback-цепочке.
