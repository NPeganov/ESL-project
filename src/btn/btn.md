# btn — логический уровень кнопки

## Назначение

`btn` получает от `btn_hw` подтверждённые изменения физического состояния кнопки и преобразует их в логические события приложения. Он не работает с GPIO и не выполняет debounce.

## Публичный интерфейс

```c
void btn_init(btn_event_handler_t event_handler);
void btn_start(void);
```

Обработчик получает один из типов `btn_event_t`: `BTN_EVENT_PRESS`, `BTN_EVENT_RELEASE`, `BTN_EVENT_SINGLE_PRESS`, `BTN_EVENT_DOUBLE_PRESS`.

Callback вызывается непосредственно из цепочки обработки подтверждённого состояния кнопки. Он должен быть коротким. В текущем приложении логирование настроено в deferred-режиме.

## Инициализация и запуск

До `btn_init()` должен быть инициализирован app_timer через `timer_service_init()`.

`btn_init()` сохраняет callback, вызывает `btn_hw_init(button_state_changed)` и создаёт собственный one-shot timer для окна двойного нажатия. Физические события ещё не включаются.

`btn_start()` делегирует запуск в `btn_hw_start()`: включаются GPIOTE events и начинается debounce первоначального состояния.

Первое подтверждённое состояние только инициализирует `m_press_started`; событие PRESS/RELEASE не генерируется. Это предотвращает ложное событие, если кнопка уже нажата во время старта.

## События

При последующих подтверждённых изменениях:

- `pressed == true`: устанавливается `m_press_started`, отправляется `BTN_EVENT_PRESS`;
- `pressed == false`: отправляется `BTN_EVENT_RELEASE`; если перед этим был press, дополнительно отправляется `BTN_EVENT_SINGLE_PRESS`.

Каждый завершённый цикл press→release формирует `SINGLE_PRESS`, в том числе тот, который впоследствии окажется частью двойного нажатия.

## Распознавание двойного нажатия

Интервал задаётся `BTN_DOUBLE_PRESS_TIME_MS`, по умолчанию 1000 мс. Отсчёт начинается от первого подтверждённого отпускания.

Если второй завершённый цикл press→release заканчивается раньше истечения интервала:

1. останавливается таймер ожидания;
2. сбрасывается признак ожидания второго нажатия;
3. отправляется дополнительное событие `BTN_EVENT_DOUBLE_PRESS`.

Таким образом, второе отпускание генерирует последовательно `RELEASE`, `SINGLE_PRESS`, `DOUBLE_PRESS`. Если окно истекло, ожидающее состояние сбрасывается и следующее отпускание начинает новое окно.

Сравнение времени выполняется средствами app_timer counter API с учётом переполнения счётчика.

## Внутреннее состояние

| Поле | Назначение |
|---|---|
| `m_state_initialized` | Получено ли первое подтверждённое состояние |
| `m_press_started` | Было ли нажатие в текущем цикле |
| `m_double_press_pending` | Открыто ли окно второго завершённого цикла |
| `m_first_release_tick` | Время первого подтверждённого отпускания |

## Зависимости и ограничения

- `btn_hw` обеспечивает подтверждённые физические состояния.
- `app_timer` используется для окна двойного нажатия.
- LFCLK и app_timer заранее подготавливает `timer_service`.
- Модуль рассчитан на один экземпляр и однократную настройку.
- `btn_init()` регистрирует callback; `btn_start()` отдельно включает обработку GPIO.
- `btn` не содержит очереди событий: события передаются callback непосредственно.

Подробности GPIO и debounce описаны в [btn_hw.md](btn_hw.md).
