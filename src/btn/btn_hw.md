# btn_hw — аппаратный уровень кнопки

## Назначение

`btn_hw` обнаруживает изменения входа кнопки PCA10059, устраняет дребезг и передаёт верхнему уровню только подтверждённое логическое состояние `pressed`.

Он не распознаёт одиночные/двойные нажатия и не знает о режимах приложения.

## Инициализация

`btn_hw_init(callback)`:

1. сохраняет callback;
2. создаёт one-shot app_timer для debounce;
3. инициализирует GPIOTE, если оно ещё не инициализировано;
4. настраивает вход кнопки с board-defined pull configuration и toggle sensing.

LFCLK и app_timer должны быть инициализированы заранее. В текущем приложении это обеспечивает `timer_service_init()`, вызванный до `btn_init()`.

`btn_hw_start()` включает GPIOTE event, считывает начальный уровень, сохраняет его как debounce candidate и запускает 10-мс таймер. Callback получает первоначальное состояние только после успешного debounce.

## Debounce

Период задаётся:

```c
#define BTN_DEBOUNCE_TIME_MS 10
```

При каждом GPIO edge:

1. считывается текущий уровень входа;
2. обновляется `m_debounce_candidate_state`;
3. предыдущий debounce timer останавливается;
4. one-shot timer запускается заново на 10 мс.

Когда timer срабатывает, вход читается повторно. Если физическое состояние отличается от сохранённого кандидата, кандидат обновляется и начинается новый полный debounce interval. Если состояние совпадает, оно считается стабильным.

После первоначального подтверждения callback вызывается только при изменении подтверждённого состояния.

## Полярность

Физический уровень преобразуется в логический `pressed` сравнением с `BUTTONS_ACTIVE_STATE` из board header. Поэтому верхний уровень получает `true` при нажатии независимо от электрической полярности входа.

## Внутреннее состояние

| Переменная | Назначение |
|---|---|
| `m_confirmed_state` | Последнее подтверждённое состояние |
| `m_debounce_candidate_state` | Состояние, ожидающее подтверждения |
| `m_initial_state_pending` | Ожидается ли первоначальный debounce |

## Граница ответственности

`btn_hw` передаёт только `bool pressed` через callback. Интерпретация этого значения как PRESS, RELEASE, SINGLE_PRESS или DOUBLE_PRESS принадлежит [btn](btn.md).

Модуль использует GPIOTE и app_timer, но не владеет общей инициализацией LFCLK/app_timer.
