# hsv_picker

## Назначение

`hsv_picker` — прикладной модуль, который связывает события кнопки с режимами HSV Picker. Он выбирает изменяемый компонент, запускает и приостанавливает его изменение, управляет индикацией режима жёлтым LED и устанавливает начальный цвет устройства.

Модуль не реализует временную математику HSV, debounce, преобразование RGB/HSV или управление PWM. Эти обязанности делегированы нижним слоям.

## Публичный интерфейс

```c
bool hsv_picker_init(void);
void hsv_picker_start(void);
```

### Инициализация

`hsv_picker_init()` выполняет:

1. `timer_service_init()` — подготавливает LFCLK и app_timer.
2. `lc_init()` — инициализирует PWM LED-драйвер, контроллеры HSV/жёлтого LED и общий 10-мс таймер.
3. Устанавливает режим `MODE_NO_INPUT` и сбрасывает флаг активного изменения.
4. Устанавливает начальный цвет HSV: вычисленный Hue, Saturation = 100%, Value = 100%.
5. Вызывает `btn_init()` и регистрирует обработчик событий.

Функция возвращает `false`, если не удалось инициализировать timer service или LED control. Ошибки внутри нижних модулей кнопки обрабатываются Nordic error mechanism.

### Запуск

`hsv_picker_start()` выключает жёлтый индикатор и вызывает `btn_start()`. Только после этого включается обнаружение пользовательских событий кнопки. Вызывать функцию можно только после успешной инициализации.

## Начальный цвет

`DEVICE_ID` сейчас равен `"6609"`. Две последние цифры трактуются как целое число процентов полного круга Hue:

```c
hue = percent * 360 / 100;
```

Для `"6609"` это 9%, то есть 32° после целочисленного деления. Saturation и Value равны 100%. Начальное значение устанавливается до старта кнопки.

## Режимы

Двойное нажатие переключает режим:

```text
NO_INPUT → HUE → SATURATION → BRIGHTNESS → NO_INPUT
```

| Режим | Параметр | Жёлтая индикация |
|---|---|---|
| `MODE_NO_INPUT` | Нет | OFF |
| `MODE_HUE` | `LC_HUE` | Медленное мигание |
| `MODE_SATURATION` | `LC_SATURATION` | Быстрое мигание |
| `MODE_BRIGHTNESS` | `LC_VALUE` | ON |

`BRIGHTNESS` — пользовательское имя режима изменения HSV Value.

В `MODE_NO_INPUT` нажатие не запускает изменение. При выборе режима `mode_advance()` сразу задаёт соответствующий паттерн жёлтого LED и пишет сообщение в лог.

## Обработка событий кнопки

| Событие | Действие |
|---|---|
| `BTN_EVENT_PRESS` | Запустить выбранный HSV-компонент, если он ещё не меняется |
| `BTN_EVENT_RELEASE` | Приостановить активное изменение |
| `BTN_EVENT_SINGLE_PRESS` | Игнорировать |
| `BTN_EVENT_DOUBLE_PRESS` | Переключить режим |

Событие двойного нажатия приходит после второго подтверждённого отпускания. Поэтому при двойном нажатии сначала обрабатывается `RELEASE` второго цикла, затем `DOUBLE_PRESS` переключает режим. Второе нажатие может кратковременно возобновить изменение прежнего режима; второе отпускание его приостанавливает до переключения.

`m_changing` не позволяет повторно запустить уже активное изменение и позволяет игнорировать отпускание, которому не предшествовал успешный старт.

## Логирование

При старте и завершении изменения модуль считывает актуальный HSV и записывает значение изменявшегося компонента. Для Value используется слово `BRIGHTNESS`. При двойном нажатии записывается новый режим. Если `lc_start_hsv_change()` возвращает ошибку, записывается сообщение об ошибке.

Логирование deferred: callback не выполняет USB-передачу напрямую; сообщения обрабатываются в main loop.

## Границы ответственности

- Выбор режима и связь режима с H/S/V принадлежат `hsv_picker`.
- Изменение значения во времени принадлежит `leds_control_hsv`.
- Паттерн жёлтого LED принадлежит `leds_control_yellow`.
- Debounce и распознавание двойного нажатия принадлежат `btn`/`btn_hw`.
- Физические LED-выходы принадлежат `leds_pwm` и `hardware/pwm`.

Полная последовательность взаимодействий описана в [сквозном описании приложения](../main.md).
