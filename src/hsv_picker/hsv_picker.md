# hsv_picker

## Назначение

`hsv_picker` — прикладной модуль HSV color picker. Он связывает пользовательский ввод с управлением цветом RGB LED:

- выбирает изменяемый компонент HSV;
- запускает изменение компонента при нажатии и приостанавливает его при отпускании кнопки;
- показывает выбранный режим с помощью жёлтого LED;
- задаёт начальный цвет устройства на основе его ID.

Модуль не реализует преобразование HSV в RGB, изменение значений по времени или физическое управление светодиодами. Эти задачи делегированы `leds_control`.

## Место в архитектуре

```text
                    main
                     |
                     v
                 hsv_picker
                  /   |   \
                 v    v    v
               btn  leds_control  timer_service
                      |                |
                      v                v
                   leds_pwm        LFCLK / app_timer

                 hsv_picker
                     |
                     v
                    log
```

`hsv_picker` использует публичные интерфейсы зависимостей:

- `btn` сообщает о подтверждённых событиях кнопки;
- `leds_control` управляет RGB LED, изменением HSV и индикацией жёлтого LED;
- `timer_service` подготавливает LFCLK и app_timer до инициализации модулей, которым нужны таймеры;
- `log` используется для сообщений о переключении режима и изменении HSV.

Выбор режима и реакция на кнопку принадлежат `hsv_picker`. Реализация изменения HSV и паттернов жёлтого LED остаётся внутри `leds_control`.

## Публичный интерфейс

Внешний код использует две функции из `hsv_picker.h`:

```c
bool hsv_picker_init(void);
void hsv_picker_start(void);
```

### `hsv_picker_init()`

Инициализирует зависимости и подготавливает начальное состояние приложения. Функция возвращает `false`, если не удалось инициализировать `timer_service` или `leds_control`.

Порядок действий:

1. `timer_service_init()` инициализирует clock driver, запускает LFCLK и инициализирует app_timer.
2. `lc_init()` инициализирует LED-драйвер, внутренние контроллеры `leds_control` и общий периодический таймер.
3. Выбирается начальное состояние `MODE_NO_INPUT`; флаг активного изменения сбрасывается.
4. В RGB LED устанавливается начальный цвет: вычисленный Hue и максимальные Saturation и Value.
5. Через `btn_init()` регистрируется обработчик событий кнопки.

Обработка пользовательских событий кнопки на этом этапе ещё не запускается.

### `hsv_picker_start()`

Включает работу приложения:

1. устанавливает для жёлтого LED паттерн `LC_YELLOW_OFF`;
2. вызывает `btn_start()`, разрешая обработку событий кнопки.

Эту функцию следует вызывать только после успешного `hsv_picker_init()`.

Таким образом, инициализация зависимостей и включение пользовательского ввода разделены. Это позволяет подготовить начальное состояние до начала взаимодействия с пользователем.

## Начальный цвет устройства

Начальные Saturation и Value всегда равны 100%.

Начальный Hue вычисляется из двух последних символов `DEVICE_ID`. Они интерпретируются как целое число процентов полного диапазона Hue:

```c
hue = percent * 360 / 100;
```

Используется целочисленное деление, поэтому дробная часть отбрасывается.

Текущая константа:

```c
#define DEVICE_ID "6609"
```

Последние две цифры дают 9%, поэтому начальный Hue равен 32°.

## Режимы управления

Текущий режим хранится в `m_mode`. Двойное нажатие переключает его по циклу:

```text
NO_INPUT -> HUE -> SATURATION -> BRIGHTNESS -> NO_INPUT
```

| Режим | Изменяемый параметр | Индикация жёлтого LED |
|---|---|---|
| `MODE_NO_INPUT` | Нет | Выключен |
| `MODE_HUE` | `LC_HUE` | Медленное мигание |
| `MODE_SATURATION` | `LC_SATURATION` | Быстрое мигание |
| `MODE_BRIGHTNESS` | `LC_VALUE` | Постоянно включён |

Название `BRIGHTNESS` используется в пользовательской логике для параметра HSV Value.

Соответствие между режимом приложения и параметром `leds_control` определяется функцией `get_mode_parameter()`. Для `MODE_NO_INPUT` функция возвращает `false`: в этом режиме удержание кнопки не запускает изменение HSV.

## Обработка кнопки

`btn` вызывает зарегистрированный обработчик непосредственно при поступлении события. Callback выполняется в interrupt context, поэтому обработчик приложения должен оставаться коротким.

`hsv_picker` обрабатывает события следующим образом:

| Событие | Действие |
|---|---|
| `BTN_EVENT_PRESS` | Запустить изменение выбранного HSV-компонента |
| `BTN_EVENT_RELEASE` | Приостановить активное изменение |
| `BTN_EVENT_SINGLE_PRESS` | Игнорировать |
| `BTN_EVENT_DOUBLE_PRESS` | Переключить режим и обновить индикацию |

### Нажатие

При `BTN_EVENT_PRESS` функция `button_press()`:

1. проверяет, что изменение ещё не запущено и выбран режим, соответствующий HSV-компоненту;
2. вызывает `lc_start_hsv_change()` для выбранного компонента;
3. устанавливает `m_changing` и записывает начальное значение параметра в лог.

Если `lc_start_hsv_change()` возвращает `false`, приложение записывает сообщение об ошибке и не устанавливает `m_changing`.

В режиме `NO_INPUT` функция сразу завершается без изменения цвета.

### Отпускание

При `BTN_EVENT_RELEASE` функция `button_release()` проверяет, было ли запущено изменение. Если да, она:

1. вызывает `lc_stop_hsv_change()`;
2. сбрасывает `m_changing`;
3. записывает итоговое значение изменявшегося параметра в лог.

Отпускание без активного изменения игнорируется.

### Переключение режима

`BTN_EVENT_DOUBLE_PRESS` вызывает `mode_advance()`. Она выбирает следующий режим, устанавливает соответствующий паттерн жёлтого LED и записывает новый режим в лог.

Событие двойного нажатия формируется `btn` после завершения второго цикла нажатия и отпускания. Поэтому отпускание, завершающее этот цикл, обрабатывается раньше переключения режима: активное изменение сначала приостанавливается, и только затем выбирается следующий компонент.

## Логирование

Модуль записывает:

- новый режим после двойного нажатия;
- значение выбранного HSV-компонента при начале изменения;
- значение этого компонента после отпускания кнопки;
- ошибку, если `lc_start_hsv_change()` не смог запустить изменение.

Для Value в пользовательских сообщениях используется название `BRIGHTNESS`.

Callback кнопки выполняется в interrupt context. Логирование используется в deferred-режиме: фактическая обработка ожидающих сообщений выполняется через `log_process()` в основном цикле приложения.

## Зависимости и ограничения

- До `hsv_picker_init()` не требуется отдельно вызывать `timer_service_init()`: это делает сам `hsv_picker`.
- `btn_init()` вызывается после инициализации timer service, поскольку модулю кнопки нужен app_timer.
- `hsv_picker_start()` предполагает, что инициализация завершилась успешно.
- Модуль хранит только выбранный режим и признак активного изменения. Текущие значения HSV принадлежат `leds_control` и нижележащему LED-драйверу.
- `hsv_picker` не задаёт скорость изменения HSV и не управляет периодическим обновлением LED напрямую. Это ответственность `leds_control`.

Подробности управления светодиодами и семантика его API описаны в [документации leds_control](leds_control/leds_control.md).
