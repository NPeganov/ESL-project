# hsv_picker

## Назначение

`hsv_picker` — прикладной координатор HSV color picker. Он связывает события кнопки с режимами H/S/V, управляет жёлтой индикацией, выбирает начальный цвет и сохраняет пользовательский цвет в энергонезависимую память.

Модуль не реализует debounce, временную математику изменения HSV, преобразование RGB/HSV или физическое управление PWM. Эти обязанности делегированы нижним слоям.

## Публичный интерфейс

```c
bool hsv_picker_init(void);
void hsv_picker_start(void);
void hsv_picker_process(void);
```

### Инициализация

`hsv_picker_init()` выполняет последовательность:

1. `nvm_log_init(HSV_FREE_VALUE_MASK)` сканирует существующие записи в Application Data Area.
2. `timer_service_init()` подготавливает LFCLK и app_timer.
3. `lc_init()` инициализирует PWM LED-драйвер, контроллеры HSV/жёлтого LED и общий 10-мс таймер.
4. Устанавливает режим `MODE_NO_INPUT`, сбрасывает флаги изменения и отложенного сохранения.
5. Пытается восстановить последнее сохранённое HSV-значение.
6. Если корректная запись отсутствует, формирует начальный цвет из `DEVICE_ID`.

Кнопка на этом этапе ещё не инициализируется: её запуск отложен до `hsv_picker_start()`, чтобы сначала подготовить начальную индикацию.

Функция возвращает `false`, если не удалось инициализировать NVM log, timer service или LED control. Ошибки внутри нижних модулей кнопки обрабатываются Nordic error mechanism.

### Запуск

`hsv_picker_start()` выключает жёлтый индикатор и вызывает `btn_init(button_event_handler)`. Внутри `btn_init()` настраиваются callback, аппаратный уровень и оба таймера кнопки, после чего включаются GPIOTE events и начинается debounce начального состояния. Вызывать функцию можно только после успешной инициализации.

### Обработка отложенных операций

`hsv_picker_process()` вызывается из основного цикла. Он атомарно забирает флаг `m_save_pending` и, если сохранение запрошено, вызывает `save_current_hsv()`. Flash programming не выполняется в callback кнопки.

## Начальный цвет и восстановление

При старте `load_saved_hsv()` запрашивает последнее значение через `nvm_log_load()`. Слово распаковывается по формату:

| Биты | Содержимое |
|---|---|
| 0…15 | Hue |
| 16…23 | Saturation |
| 24…31 | Value |

Перед применением проверяются диапазоны: H — 0…359, S и V — 0…100. Корректная запись имеет приоритет над значением устройства. После восстановления в лог выводятся все три компонента.

Если запись отсутствует или её HSV-компоненты некорректны, начальное состояние вычисляется из `DEVICE_ID`. Последние две цифры ID трактуются как процент полного круга Hue:

```c
hue = percent * 360 / 100;
```

Для `DEVICE_ID = "6609"` процент равен 9, поэтому начальное состояние — H = 32°, S = 100%, V = 100%. В лог выводятся источник и все три компонента выбранного стартового состояния.

## Режимы

Двойное нажатие переключает режим:

```text
NO_INPUT → HUE → SATURATION → BRIGHTNESS → NO_INPUT
```

| Режим | Параметр | Жёлтая индикация |
|---|---|---|
| `MODE_NO_INPUT` | Нет | OFF |
| `MODE_HUE` | `LC_HUE` | Медленное мигание |
| `MODE_SATURATION` | `LC_SATURATION` | Быстрое мигание |
| `MODE_BRIGHTNESS` | `LC_VALUE` | ON |

`BRIGHTNESS` — пользовательское имя режима изменения HSV Value.

В `MODE_NO_INPUT` нажатие не запускает изменение. При выборе режима `mode_advance()` задаёт соответствующий паттерн жёлтого LED и пишет сообщение в лог.

## Обработка событий кнопки

| Событие | Действие |
|---|---|
| `BTN_EVENT_PRESS` | Подтверждает начало физического нажатия; HSV не меняется |
| `BTN_EVENT_HOLD` | Запускает изменение выбранного HSV-компонента, если режим не `NO_INPUT` |
| `BTN_EVENT_RELEASE` | Останавливает активное изменение и сохраняет его прогресс |
| `BTN_EVENT_SINGLE_PRESS` | Игнорируется |
| `BTN_EVENT_DOUBLE_PRESS` | Переключает режим |

Порог HOLD задаётся в модуле `btn` и сейчас равен 250 мс. Короткое нажатие не запускает изменение HSV. Это принципиально для двойного нажатия: первый короткий цикл остаётся кандидатом на DOUBLE_PRESS и не начинает менять параметр.

Второй короткий цикл формирует `RELEASE`, затем `SINGLE_PRESS`, затем `DOUBLE_PRESS`. Переключение режима происходит только после распознавания завершённого двойного нажатия. Если удержание достигает порога HOLD, HSV-изменение начинается; HOLD отменяет ожидающее окно двойного нажатия, а последующий RELEASE завершает изменение без генерации SINGLE_PRESS.

`m_hsv_change_active` отражает фактическое состояние изменения. `m_active_parameter` сохраняет параметр, который был выбран при старте, поэтому при завершении логируется именно изменявшийся параметр.

## Сохранение HSV

Сохранение запрашивается при переходе из `MODE_BRIGHTNESS` в `MODE_NO_INPUT`, то есть после полного цикла выбора H, S и V. Сам callback кнопки только устанавливает `m_save_pending`. Основной цикл вызывает `hsv_picker_process()`, который выполняет чтение текущих H/S/V, упаковку в 32-битное слово и `nvm_log_save()`.

Если запись успешна, выводится `Saved HSV color: H=... S=... V=...`. При ошибке выводится `Failed to save HSV color`; сообщение об успешном сохранении в этом случае не появляется. Удержание кнопки и промежуточные изменения отдельных параметров сами по себе не запускают flash write.

Формат flash-записи и политика хранения принадлежат `nvm_log`; упаковка и проверка HSV принадлежат вызывающему слою `hsv_picker`.

## Логирование

При старте и завершении изменения модуль считывает актуальный HSV и записывает значение изменявшегося компонента. Для Value используется слово `BRIGHTNESS`. При двойном нажатии записывается новый режим.

Отдельно логируются:
- восстановленное из памяти стартовое значение H/S/V;
- начальное значение H/S/V, сформированное из `DEVICE_ID`, если корректной записи нет;
- успешное сохранение H/S/V или ошибка записи.

Логирование deferred: callback не выполняет USB-передачу напрямую; сообщения обрабатываются в main loop.

## Границы ответственности

- Выбор режима, начальный HSV, упаковка/распаковка HSV и решение о моменте сохранения принадлежат `hsv_picker`.
- Хранение последовательных 32-битных записей во flash принадлежит `nvm_log`.
- Изменение значения во времени принадлежит `leds_control_hsv`.
- Паттерн жёлтого LED принадлежит `leds_control_yellow`.
- Debounce принадлежит `btn_hw`; распознавание короткого/двойного нажатия и HOLD — `btn`.
- Физические LED-выходы принадлежат `leds_pwm` и `hardware/pwm`.

Полная последовательность взаимодействий описана в [сквозном описании приложения](../main.md).
