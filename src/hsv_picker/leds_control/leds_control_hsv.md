# leds_control_hsv

## Назначение

`leds_control_hsv` — внутренний контроллер, который изменяет один выбранный HSV-компонент RGB LED во времени.

Контроллер не знает о кнопке и режимах приложения. Координатор сообщает ему, какой параметр начать изменять, когда приостановить изменение и когда выполнить очередное обновление.

Физическое состояние RGB LED хранится и изменяется через `leds_pwm`.

## Внутренний интерфейс

```c
void hsv_init(void);
bool hsv_start(lc_hsv_parameter_t parameter);
void hsv_stop(void);
void hsv_process(uint32_t now);
```

Эти функции являются внутренним интерфейсом `leds_control`, а не публичным API приложения.

## Состояния контроллера

Контроллер использует три состояния:

| Состояние | Значение |
|---|---|
| `CHANGE_IDLE` | изменение не запущено |
| `CHANGE_RUNNING` | выбранный параметр изменяется |
| `CHANGE_PAUSED` | изменение приостановлено, прогресс сохранён |

`hsv_init()` переводит контроллер в `CHANGE_IDLE`.

## Запуск и переключение параметра

`hsv_start(parameter)` сначала проверяет допустимость enum.

Дальнейшее поведение зависит от текущего состояния:

1. Если тот же параметр уже изменяется, функция ничего не перезапускает и возвращает `true`.
2. Если тот же параметр был приостановлен, изменение возобновляется с сохранённой фазой.
3. Если выбран другой параметр, контроллер сначала применяет накопившееся изменение предыдущего параметра до текущего момента. Затем читает актуальные H, S и V из `leds_pwm`, сохраняет текущее значение нового компонента как начальное, обнуляет накопленное время и запускает новый цикл.

Новый цикл начинается от текущего значения компонента, а не от фиксированного значения 0 или 100. При переключении параметра предыдущая фаза не сохраняется.

## Приостановка и возобновление

`hsv_stop()` действует только в состоянии `CHANGE_RUNNING`.

Перед переходом в `CHANGE_PAUSED` контроллер обрабатывает интервал от последнего callback до момента остановки. Это не позволяет потерять время, прошедшее между периодическим обновлением и нажатием кнопки.

При возобновлении того же параметра обновляется timestamp последнего старта. Накопленное активное время и фаза цикла сохраняются, а время паузы в расчёт не входит.

## Алгоритм изменения Hue

Период полного оборота Hue задаётся константой:

```c
#define HUE_CYCLE_DURATION_MS 10000
```

Hue непрерывно увеличивается и проходит полный диапазон 0…359 градусов за 10 секунд. После полного оборота значение возвращается к исходному:

```c
next_hue = (start_value + hue_delta) % 360;
```

Смещение вычисляется по суммарному активному времени от начала текущего запуска. Оно не накапливается прибавлением к предыдущему результату, поэтому задержки отдельных callback не приводят к накоплению арифметического дрейфа.

## Алгоритм изменения Saturation и Value

Для Saturation и Value используется треугольная волна в диапазоне 0…100%. Один полупериод — движение от одного края диапазона к другому. По достижении края направление меняется.

Продолжительность полупериода задаётся отдельными константами:

```c
#define SATURATION_HALF_CYCLE_MS 5000
#define VALUE_HALF_CYCLE_MS      5000
```

Сейчас обе константы равны 5 секундам, но настраиваются независимо. Полный цикл от 0 до 100 и обратно при текущих настройках занимает 10 секунд.

Начальная фаза определяется текущим значением компонента: если оно меньше 100, изменение сначала движется вверх; если равно 100 — вниз. Расчёт выполняется от начального значения и суммарного активного времени, а не от результата предыдущего callback.

Одновременно изменяется только один компонент — тот, который был выбран при запуске.

## Периодическая обработка

`hsv_process(now)` вызывается координатором каждые 10 мс. Параметр `now` — текущее значение счётчика app_timer, полученное общим callback.

Если контроллер не находится в `CHANGE_RUNNING`, функция сразу возвращается.

В активном состоянии она:

1. добавляет прошедшие тики к `elapsed_ticks`;
2. сохраняет текущий timestamp;
3. считывает актуальные H, S и V из `leds_pwm`;
4. вычисляет новое значение выбранного компонента из начального значения и суммарного активного времени;
5. вызывает `leds_pwm_set_hsv()`, только если цвет действительно изменился.

Два остальных HSV-компонента сохраняются без изменений. Разница timestamp вычисляется через `app_timer_cnt_diff_compute()`, поэтому учитывается переполнение счётчика app_timer.

## Внутренние данные

| Переменная | Назначение |
|---|---|
| `change_state` | состояние автомата |
| `active_parameter` | изменяемый компонент HSV |
| `start_value` | значение компонента в начале текущего цикла |
| `elapsed_ticks` | суммарное активное время, без пауз |
| `last_tick` | timestamp предыдущего обновления или возобновления |

Контроллер не хранит отдельную копию полного HSV-цвета: он получает текущее значение у `leds_pwm` перед обновлением.

## Граница ответственности

`leds_control_hsv` отвечает только за временную математику изменения одного HSV-компонента. Он не:

- обрабатывает события кнопки;
- выбирает следующий режим приложения;
- управляет жёлтым LED;
- создаёт таймер;
- непосредственно управляет PWM-каналами.

Общий таймер и физический вывод принадлежат соседним уровням `leds_control` и `leds_pwm`.
