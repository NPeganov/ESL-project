# leds_control_hsv

## Назначение

`leds_control_hsv` — внутренний контроллер, который изменяет один выбранный HSV-компонент RGB-светодиода во времени.

Он не знает о кнопке и о режимах приложения. Верхний уровень сообщает ему, какой параметр начать изменять, когда приостановить изменение и когда выполнить очередное обновление.

Физическое состояние RGB LED хранится и изменяется через `leds_pwm`.

## Внутренний интерфейс

```c
void hsv_init(void);
bool hsv_start(lc_hsv_parameter_t parameter);
void hsv_stop(void);
void hsv_process(uint32_t now);
```

Эти функции являются внутренним интерфейсом `leds_control`, а не публичным API приложения.

## Состояния контроллера

Контроллер использует три состояния:

| Состояние | Значение |
|---|---|
| `CHANGE_IDLE` | изменение не запускалось или завершено сбросом |
| `CHANGE_RUNNING` | параметр изменяется |
| `CHANGE_PAUSED` | изменение приостановлено, фаза сохранена |

`hsv_init()` сбрасывает автомат в `CHANGE_IDLE`. Начальные значения остальных полей не требуются, пока автомат не запущен.

## Запуск и переключение параметра

`hsv_start(parameter)` сначала проверяет значение enum.

Дальнейшее поведение зависит от текущего состояния:

1. Если тот же параметр уже изменяется, функция ничего не перезапускает и возвращает `true`.
2. Если тот же параметр был приостановлен, изменение возобновляется с сохранённой фазой.
3. Если выбран другой параметр, контроллер читает актуальные H, S и V из `leds_pwm`, сохраняет начальное значение выбранного компонента, обнуляет накопленное время и запускает новое изменение.

При запуске нового параметра точкой отсчёта служит текущее значение компонента, а не фиксированное значение 0 или 100.

Если переключиться с одного параметра на другой во время изменения, новый параметр начинает собственный цикл от своего текущего значения. Предыдущая фаза больше не сохраняется.

## Приостановка и возобновление

`hsv_stop()` действует только в состоянии `CHANGE_RUNNING`.

Перед переходом в `CHANGE_PAUSED` контроллер добавляет к накопленному времени интервал от последнего callback до момента остановки. Поэтому пауза не теряет время, прошедшее между последним периодическим обновлением и нажатием кнопки.

При возобновлении того же параметра обновляется только timestamp последнего старта. Накопленное активное время и направление движения сохраняются. Время, проведённое на паузе, в расчёт не входит.

## Алгоритм изменения Hue

Период полного оборота Hue задаётся:

```c
#define HUE_CYCLE_DURATION_MS 10000
```

Hue непрерывно увеличивается и проходит полный диапазон 0…359 за 10 секунд. После полного оборота значение возвращается к исходному:

```c
next_hue = (start_value + hue_delta) % 360;
```

Смещение вычисляется по суммарному активному времени от начала текущего запуска. Оно не накапливается прибавлением к предыдущему результату, поэтому задержки отдельных callback не приводят к накоплению арифметического дрейфа.

## Алгоритм изменения Saturation и Value

Для Saturation и Value используется одна треугольная волна:

```c
#define HSV_VALUE_HALF_CYCLE_MS 5000
```

Один проход от 0 до 100 или от 100 до 0 занимает 5 секунд. Полный цикл 0 → 100 → 0 занимает 10 секунд.

Начальная фаза определяется текущим значением компонента. Далее значение движется по треугольной волне в диапазоне 0…100, без выхода за границы. Если начальное значение равно 100, волна начинает движение вниз.

Saturation и Value используют один и тот же алгоритм и одинаковые временные параметры. Одновременно изменяется только один из них — тот, который был выбран при запуске.

## Периодическая обработка

`hsv_process(now)` вызывается координатором каждые 10 мс.

Если контроллер не находится в `CHANGE_RUNNING`, функция сразу возвращается.

В активном состоянии она:

1. добавляет прошедшие тики к `elapsed_ticks`;
2. сохраняет текущий timestamp;
3. считывает актуальные H, S и V из `leds_pwm`;
4. вычисляет новое значение выбранного компонента из начального значения и суммарного активного времени;
5. вызывает `leds_pwm_set_hsv()`, только если цвет действительно изменился.

Два других HSV-компонента сохраняются без изменений.

## Внутренние данные

| Поле | Назначение |
|---|---|
| `change_state` | состояние автомата |
| `active_parameter` | изменяемый компонент HSV |
| `start_value` | значение компонента в начале текущего запуска |
| `elapsed_ticks` | суммарное активное время, без пауз |
| `last_tick` | timestamp предыдущего обновления или возобновления |

Все поля нужны для расчёта абсолютной фазы и корректной паузы/возобновления. Контроллер не хранит отдельную копию полного HSV-цвета: он получает текущее значение у `leds_pwm` перед обновлением.

## Граница ответственности

`leds_control_hsv` отвечает только за временную математику изменения одного HSV-компонента. Он не:

- обрабатывает события кнопки;
- выбирает следующий режим приложения;
- управляет жёлтым LED;
- создаёт таймер;
- непосредственно управляет PWM-каналами.

Общий таймер и физический вывод принадлежат соседним уровням `leds_control` и `leds_pwm`.
