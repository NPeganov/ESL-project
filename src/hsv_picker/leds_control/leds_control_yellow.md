# leds_control_yellow

## Назначение

`leds_control_yellow` — внутренний контроллер жёлтого индикатора HSV Picker. Он применяет один из заданных паттернов и обновляет яркость жёлтого LED через `leds_pwm`.

Модуль не создаёт собственный таймер. Периодическую обработку вызывает координатор `leds_control`, передавая текущее значение счётчика app_timer.

## Внутренний интерфейс

```c
void yellow_init(void);
bool yellow_set_pattern(lc_yellow_pattern_t pattern);
void yellow_process(uint32_t now);
```

Эти функции являются внутренним интерфейсом `leds_control`.

## Паттерны

Поддерживаются четыре значения:

| Паттерн | Начальное состояние | Дальнейшее поведение |
|---|---|---|
| `LC_YELLOW_OFF` | выключен | остаётся выключенным |
| `LC_YELLOW_ON` | включён | остаётся включённым |
| `LC_YELLOW_SLOW_BLINK` | включён | переключение каждые 1000 мс |
| `LC_YELLOW_FAST_BLINK` | включён | переключение каждые 150 мс |

Интервалы задаются константами:

```c
#define YELLOW_SLOW_BLINK_MS 1000
#define YELLOW_FAST_BLINK_MS 150
```

Указанный интервал — время между соседними переключениями. Поэтому полный цикл «включён + выключен» занимает 2000 мс для медленного паттерна и 300 мс для быстрого.

## Инициализация

`yellow_init()` сбрасывает только логическое состояние:

```c
pattern = LC_YELLOW_OFF;
state = false;
```

Функция не обращается к `app_timer` и не меняет физическую яркость LED. Начальное выключение физического выхода выполняет координатор `leds_control` в `lc_init()`, сразу после успешной инициализации `leds_pwm`.

Так внутренний контроллер отвечает за состояние паттерна, а начальная настройка аппаратного выхода остаётся на уровне модуля, который организует всю подсистему.

## Установка паттерна

`yellow_set_pattern(new_pattern)` проверяет enum и сразу применяет соответствующее выходное состояние:

- OFF — яркость 0%;
- ON и оба режима мигания — яркость 100%.

Для любого принятого паттерна функция обновляет `pattern` и записывает текущий timestamp в `toggle_tick`. Поэтому запуск мигания всегда начинается с включённого состояния и отсчитывает первый интервал от момента установки паттерна.

Неизвестное значение enum отклоняется: функция возвращает `false` и не применяет новый паттерн.

## Периодическая обработка

`yellow_process(now)` вызывается общим таймером каждые 10 мс.

Для OFF и ON функция ничего не делает. Для мигающих паттернов она:

1. выбирает интервал переключения;
2. вычисляет число полностью прошедших интервалов от `toggle_tick`;
3. сдвигает `toggle_tick` на целое число интервалов;
4. проверяет чётность числа переключений;
5. меняет физическое состояние LED только при нечётном числе пропущенных переключений.

Сдвиг timestamp на целое число интервалов, а не установка его равным `now`, сохраняет фазу мигания и не накапливает дрейф из-за задержек callback.

Если за время между вызовами прошло чётное число переключений, конечное состояние LED совпадает с исходным и запись в PWM не требуется.

## Внутренние данные

| Поле | Назначение |
|---|---|
| `pattern` | выбранный паттерн |
| `state` | фактическое логическое состояние LED |
| `toggle_tick` | timestamp последнего планового переключения |

`toggle_tick` устанавливается при каждом вызове `yellow_set_pattern()`. Пока паттерн OFF или ON, timestamp не используется.

## Граница ответственности

Контроллер управляет только логикой жёлтого индикатора. Он не:

- выбирает паттерн в зависимости от режима приложения;
- обрабатывает кнопку;
- создаёт или запускает app_timer;
- управляет RGB-цветом;
- настраивает GPIO или PWM напрямую.

Выбор паттерна делает `hsv_picker`, общий таймер принадлежит `leds_control`, физическая яркость задаётся через `leds_pwm`.
