# leds_control_yellow

## Назначение

`leds_control_yellow` — внутренний контроллер жёлтого индикатора HSV Picker. Он применяет выбранный паттерн и обновляет яркость жёлтого LED через `leds_pwm`.

Модуль не создаёт собственный таймер. Периодическую обработку вызывает координатор `leds_control`, передавая текущее значение счётчика app_timer.

## Внутренний интерфейс

```c
void yellow_init(void);
bool yellow_set_pattern(lc_yellow_pattern_t pattern);
void yellow_process(uint32_t now);
```

Эти функции являются внутренним интерфейсом `leds_control`, а не API приложения.

## Паттерны и временные параметры

Поддерживаются четыре паттерна:

| Паттерн | Поведение |
|---|---|
| `LC_YELLOW_OFF` | яркость 0% |
| `LC_YELLOW_ON` | яркость 100% |
| `LC_YELLOW_SLOW_BLINK` | плавный медленный цикл |
| `LC_YELLOW_FAST_BLINK` | плавный быстрый цикл |

Мигающие паттерны состоят из четырёх последовательных фаз:

1. плавное нарастание яркости от 0 до 100%;
2. выдержка при яркости 100%;
3. плавное снижение яркости от 100 до 0%;
4. выдержка при яркости 0%.

Продолжительность фаз задаётся отдельными константами:

| Фаза | Медленный паттерн | Быстрый паттерн |
|---|---:|---:|
| Нарастание | 1000 мс | 150 мс |
| Выдержка включённого состояния | 200 мс | 50 мс |
| Снижение | 1000 мс | 150 мс |
| Выдержка выключенного состояния | 200 мс | 50 мс |
| **Полный цикл** | **2400 мс** | **400 мс** |

Таким образом, медленный паттерн плавно проходит полный цикл за 2,4 секунды, быстрый — за 0,4 секунды. Это не переключение между двумя фиксированными состояниями: в фазах нарастания и снижения яркость меняется линейно.

## Инициализация

`yellow_init()` сбрасывает логическое состояние, устанавливая выбранный паттерн в `LC_YELLOW_OFF`.

Функция не обращается к app_timer и не меняет физическую яркость LED. Начальное выключение физического выхода выполняет координатор `leds_control` в `lc_init()`, сразу после успешной инициализации `leds_pwm`.

## Установка паттерна

`yellow_set_pattern(new_pattern)` проверяет enum и сразу применяет начальную яркость:

- OFF — 0%;
- ON — 100%;
- оба мигающих паттерна — 0%.

Для мигающего паттерна функция переводит длительности четырёх фаз в тики app_timer, вычисляет полную длительность цикла и сохраняет timestamp его начала. Поэтому новый цикл всегда начинается с нулевой яркости и фазы нарастания.

При переключении с одного паттерна на другой предыдущая фаза не продолжается: новый паттерн начинается заново. Для OFF и ON яркость устанавливается сразу, периодический расчёт не требуется.

Неизвестное значение enum отклоняется: функция возвращает `false` и не применяет новый паттерн.

## Расчёт яркости

Внутренняя функция `get_blink_brightness(phase_ticks)` вычисляет яркость для текущей позиции внутри цикла.

Границы фаз последовательно рассчитываются из длительностей:

- конец нарастания;
- конец выдержки при полной яркости;
- конец снижения;
- оставшаяся часть цикла — выдержка при нулевой яркости.

В фазе нарастания яркость линейно увеличивается пропорционально прошедшему времени. В фазе снижения она линейно уменьшается. Для двух фаз выдержки возвращаются соответственно 100% и 0%.

Функция только рассчитывает значение и не обращается к PWM. Применение результата выполняет `yellow_process()`.

## Периодическая обработка

`yellow_process(now)` вызывается общим таймером каждые 10 мс.

Для паттернов OFF и ON функция сразу возвращается. Для мигающих паттернов она:

1. вычисляет время, прошедшее с начала паттерна;
2. находит позицию внутри текущего цикла с помощью остатка от деления на длительность цикла;
3. рассчитывает яркость для соответствующей фазы;
4. сравнивает её с текущей яркостью из `leds_pwm`;
5. обновляет PWM только при изменении яркости.

Положение внутри цикла вычисляется от исходного timestamp, а не накоплением времени между callback. Поэтому задержка отдельного вызова не сдвигает последующие циклы и не приводит к накоплению временного дрейфа.

Сравнение с текущей яркостью позволяет не выполнять лишние записи в PWM, если рассчитанное значение не изменилось.

## Внутренние данные

| Переменная | Назначение |
|---|---|
| `pattern` | выбранный паттерн |
| `timing` | длительности четырёх фаз и полного цикла в тиках app_timer |
| `pattern_start_tick` | timestamp начала текущего мигающего паттерна |

Структура `blink_timing_t` содержит длительности фаз нарастания, выдержки включённого состояния, снижения и выдержки выключенного состояния, а также суммарную длительность цикла.

## Граница ответственности

Контроллер отвечает только за логику яркости жёлтого индикатора. Он не:

- выбирает паттерн в зависимости от режима приложения;
- обрабатывает кнопку;
- создаёт или запускает app_timer;
- управляет RGB-цветом;
- настраивает GPIO или PWM напрямую.

Выбор паттерна делает `hsv_picker`, общий таймер принадлежит `leds_control`, а физическая яркость задаётся через `leds_pwm`.
