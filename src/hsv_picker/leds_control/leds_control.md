# leds_control

## Назначение

`leds_control` — публичный фасад управления светодиодами в приложении HSV Picker. Он объединяет три задачи:

- инициализирует `leds_pwm`;
- предоставляет API для установки и чтения цвета RGB LED в HSV-представлении;
- координирует изменение HSV и паттерны жёлтого LED через один периодический таймер.

Модуль не обрабатывает кнопку и не определяет режимы приложения. Выбор того, какой параметр HSV изменять и какой паттерн индикации использовать, остаётся за `hsv_picker`.

## Место в архитектуре

```text
hsv_picker
    |
    v
leds_control
    |---------------------|
    v                     v
leds_control_hsv    leds_control_yellow
    |                     |
    +----------+----------+
               |
               v
            leds_pwm
               |
               v
          hardware/pwm
```

`leds_control_hsv` и `leds_control_yellow` — внутренние части модуля. Приложение использует только `leds_control.h`.

## Публичный API

### Инициализация

```c
bool lc_init(void);
```

Функция выполняет следующую последовательность:

1. отклоняет повторную инициализацию;
2. вызывает `leds_pwm_init()`;
3. явно устанавливает яркость жёлтого LED в 0%;
4. сбрасывает внутреннее состояние HSV-контроллера через `hsv_init()`;
5. сбрасывает логическое состояние жёлтого контроллера через `yellow_init()`;
6. создаёт повторяющийся app_timer;
7. запускает таймер с периодом 10 мс.

Инициализация LFCLK и самого app_timer выполняется выше, через `timer_service_init()`. Поэтому `timer_service_init()` должен быть вызван до `lc_init()`.

Функция возвращает `false`, если модуль уже инициализирован или не удалось инициализировать PWM либо создать/запустить таймер.

### Установка и чтение HSV

```c
void lc_set_hsv(
    uint16_t hue,
    uint8_t saturation,
    uint8_t value);

void lc_get_hsv(
    uint16_t *hue,
    uint8_t *saturation,
    uint8_t *value);
```

Функции напрямую делегируют работу в `leds_pwm`.

Диапазоны:

| Параметр | Диапазон |
|---|---:|
| Hue | 0…359 градусов |
| Saturation | 0…100% |
| Value | 0…100% |

Все три указателя в `lc_get_hsv()` должны быть действительными.

### Изменение HSV при удержании кнопки

```c
bool lc_start_hsv_change(lc_hsv_parameter_t parameter);
void lc_stop_hsv_change(void);
```

`lc_start_hsv_change()` начинает изменение выбранного компонента или возобновляет приостановленное изменение того же компонента. Допустимые значения:

- `LC_HUE`;
- `LC_SATURATION`;
- `LC_VALUE`.

Функция возвращает `false`, если `leds_control` ещё не инициализирован или параметр недопустим.

`lc_stop_hsv_change()` приостанавливает текущее изменение. Его фазу можно продолжить повторным вызовом `lc_start_hsv_change()` с тем же параметром.

### Паттерн жёлтого LED

```c
bool lc_set_yellow_pattern(lc_yellow_pattern_t pattern);
```

Поддерживаются:

| Значение | Поведение |
|---|---|
| `LC_YELLOW_OFF` | выключить LED |
| `LC_YELLOW_SLOW_BLINK` | медленное мигание |
| `LC_YELLOW_FAST_BLINK` | быстрое мигание |
| `LC_YELLOW_ON` | постоянно включить LED |

Новый паттерн применяется сразу. Для мигающих паттернов начальное состояние — включённый LED.

Функция возвращает `false`, если модуль не инициализирован или передан неизвестный паттерн.

## Общий таймер

`leds_control` создаёт один повторяющийся таймер с интервалом 10 мс. В callback timestamp считывается один раз:

```c
uint32_t now = app_timer_cnt_get();

hsv_process(now);
yellow_process(now);
```

Оба контроллера получают один и тот же момент времени. Это упрощает синхронизацию и исключает необходимость создавать отдельные app_timer для HSV и жёлтого LED.

Таймер работает независимо от того, активны ли в данный момент оба контроллера: каждый из них быстро возвращается, если ему нечего обновлять.

## Начальное состояние жёлтого LED

Физический выход выключается непосредственно в `lc_init()` после успешного `leds_pwm_init()`:

```c
leds_pwm_set_yellow_brightness(0);
```

Затем `yellow_init()` сбрасывает только логическое состояние паттерна. Такое разделение оставляет физическую настройку выхода на уровне координатора, а внутреннему контроллеру — только его собственное состояние.

## Зависимости и ограничения

`leds_control` зависит от:

- `timer_service` — должен заранее инициализировать LFCLK и app_timer;
- `leds_pwm` — физическое управление LED;
- `app_timer` — общий периодический callback.

Модуль рассчитан на один экземпляр и однократную инициализацию. Он не владеет кнопкой, не переключает режимы приложения и не хранит отдельную копию текущего HSV: источником актуального цвета остаётся `leds_pwm`.
