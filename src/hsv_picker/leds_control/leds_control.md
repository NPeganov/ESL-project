# leds_control

## Назначение

`leds_control` — публичный фасад управления светодиодами приложения HSV Picker. Он:

- инициализирует аппаратный LED-драйвер `leds_pwm`;
- предоставляет API для установки и чтения цвета RGB LED в HSV-представлении;
- запускает и приостанавливает изменение выбранного HSV-компонента;
- задаёт паттерн индикации жёлтого LED;
- координирует оба внутренних контроллера одним периодическим таймером.

Модуль не обрабатывает кнопку и не выбирает режим приложения. Выбор HSV-компонента и соответствующего паттерна жёлтого LED остаётся за `hsv_picker`.

## Место в архитектуре

```text
hsv_picker
    |
    v
leds_control
    |---------------------|
    v                     v
leds_control_hsv    leds_control_yellow
    |                     |
    +----------+----------+
               |
               v
            leds_pwm
               |
               v
          hardware/pwm
```

`leds_control_hsv` и `leds_control_yellow` — внутренние части подсистемы. Приложение использует только интерфейс из `leds_control.h`. Физическое управление RGB- и жёлтым LED выполняет `leds_pwm`.

## Публичный API

### Инициализация

```c
bool lc_init(void);
```

Функция выполняет следующие действия:

1. отклоняет повторную инициализацию;
2. инициализирует `leds_pwm`;
3. выключает жёлтый LED, устанавливая яркость 0%;
4. сбрасывает состояние HSV-контроллера через `hsv_init()`;
5. сбрасывает состояние контроллера жёлтого LED через `yellow_init()`;
6. создаёт повторяющийся app_timer;
7. запускает его с периодом 10 мс.

LFCLK и app_timer должны быть инициализированы заранее. В приложении это обеспечивает `timer_service_init()`, который должен быть вызван до `lc_init()`.

Функция возвращает `false`, если модуль уже инициализирован, не удалось инициализировать PWM или создать/запустить таймер. При ошибке запуска таймера флаг инициализации сбрасывается.

### Установка и чтение HSV

```c
void lc_set_hsv(
    uint16_t hue,
    uint8_t saturation,
    uint8_t value);

void lc_get_hsv(
    uint16_t *hue,
    uint8_t *saturation,
    uint8_t *value);
```

Обе функции напрямую делегируют работу в `leds_pwm`. Отдельную копию HSV модуль не хранит.

| Параметр | Диапазон |
|---|---:|
| Hue | 0…359 градусов |
| Saturation | 0…100% |
| Value | 0…100% |

Все три указателя в `lc_get_hsv()` должны быть действительными.

### Изменение HSV

```c
bool lc_start_hsv_change(lc_hsv_parameter_t parameter);
void lc_stop_hsv_change(void);
```

`lc_start_hsv_change()` начинает изменение выбранного компонента или возобновляет приостановленное изменение того же компонента. Допустимые значения:

- `LC_HUE`;
- `LC_SATURATION`;
- `LC_VALUE`.

Повторный запуск уже изменяемого компонента не сбрасывает его прогресс. При запуске другого компонента предыдущий цикл сначала обновляется до текущего момента, после чего новый компонент начинает собственный цикл от своего текущего значения.

Функция возвращает `false`, если `leds_control` ещё не инициализирован или передан недопустимый параметр.

`lc_stop_hsv_change()` приостанавливает активное изменение. Повторный запуск того же компонента продолжает сохранённую фазу; время паузы в расчёт не входит.

### Паттерн жёлтого LED

```c
bool lc_set_yellow_pattern(lc_yellow_pattern_t pattern);
```

Поддерживаются четыре паттерна:

| Значение | Поведение |
|---|---|
| `LC_YELLOW_OFF` | яркость 0% |
| `LC_YELLOW_SLOW_BLINK` | плавный медленный цикл |
| `LC_YELLOW_FAST_BLINK` | плавный быстрый цикл |
| `LC_YELLOW_ON` | яркость 100% |

При выборе мигающего паттерна цикл начинается с нулевой яркости и плавного нарастания. Параметры фаз описаны в документе [leds_control_yellow.md](leds_control_yellow.md).

Функция возвращает `false`, если модуль не инициализирован или передан неизвестный паттерн.

## Общий таймер

`leds_control` создаёт один повторяющийся таймер с интервалом 10 мс. В callback значение счётчика считывается один раз:

```c
uint32_t now = app_timer_cnt_get();

hsv_process(now);
yellow_process(now);
```

Оба контроллера получают один timestamp и используют общую временную шкалу. Отдельные таймеры для HSV и жёлтого LED не нужны.

Таймер продолжает вызывать оба обработчика независимо от их активности. Если контроллеру нечего обновлять, его обработчик быстро возвращается.

## Начальное состояние жёлтого LED

Физический выход выключается непосредственно в `lc_init()` после успешной инициализации `leds_pwm`:

```c
leds_pwm_set_yellow_brightness(0);
```

После этого `yellow_init()` сбрасывает логическое состояние паттерна. Такое разделение оставляет начальную настройку физического выхода на уровне координатора, а внутреннему контроллеру — управление паттерном.

## Зависимости и ограничения

`leds_control` зависит от:

- `timer_service` — должен заранее инициализировать LFCLK и app_timer;
- `leds_pwm` — физическое управление LED;
- `app_timer` — общий периодический callback.

Модуль рассчитан на один экземпляр и однократную успешную инициализацию. Он не владеет кнопкой, не переключает режимы приложения и не хранит отдельную копию текущего HSV: источником актуального цвета остаётся `leds_pwm`.
